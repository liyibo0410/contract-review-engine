## 一、需求基线 8 条验收标准

### ① 能接入并解析 DOCX、PDF 及图片扫描件格式的合同附件

| 项 | 内容 |
| --- | --- |
| 实现位置 | `app/parsers.py`（格式探测 → DOCX/PDF 解析器）、`app/ocr_win.py`（Windows 内置 OCR 通道） |
| 验证方式 | 对 `samples/` 下三种格式各解析一次，校验 `ok` 与字符数 |
| 实测结果 | DOCX：引擎 `docx-xml`，36 段 / 1157 字符；PDF：引擎 `pdf-text`，2 页 / 59 段 / 1562 字符；扫描件 PNG：引擎 `ocr-win`，18 段 / 407 字符，OCR 置信度 1.00 |

### ② 能准确提取合同核心元数据与主要条款内容，并记录原文页码与位置

| 项 | 内容 |
| --- | --- |
| 实现位置 | 元数据：`app/review.py::extract_metadata`；条款切分：`split_clauses` + `config/clause_types.json`（16 类） |
| 验证方式 | 校验元数据字段非空；对每条带锚点的命中，回算 `char_start - 段落.char_start` 并在段落原文中切片，核对片段非空且落在正文内 |
| 实测结果 | 相对方=深智远科技有限公司，统一社会信用代码=91130100MA0D8YQK5T，金额=2,860,000.00，期限已抽取；带定位锚点命中 3 条，**锚点与原文片段一致性校验全部通过**；切分 27 个条款，条款类型覆盖度 69%（11/16 类） |

### ③ 能对必备条款缺失、权责不对等与高危表述完成合规审查，输出风险等级与依据

| 项 | 内容 |
| --- | --- |

| 实测结果 | 采购风险用例命中 `PU-H-001`（知识产权归供应商）、`PU-H-002`（到货即付全款）、`PU-M-001`；销售合同命中 `SA-H-001`（违约责任不对等，双侧证据合并）；劳动合同命中 `LA-H-001`、`LA-H-002`、`LA-M-001`、`LA-M-002`。**标准用例命中 0 条**（采购标准用例、服务标准用例均无误报）。01 综合风险=高风险/建议拒绝；03 综合风险=高风险/需整改 |
| 截图 | `docs/screenshots/02_智能审查工作台_风险用例.png`、`03_权责不对等审查_销售合同.png` |

### ④ 能在审查工作台实现原文与风险卡片的双向高亮定位与跳转

| 项 | 内容 |

| --- | --- |

### ⑦ 解析失败或接口异常时能正确进入阻塞状态并支持重试

| 项 | 内容 |
| --- | --- |
| 实现位置 | 解析侧：`app/pipeline.py`（`block_on_parse_fail`，写入 `blocked` 与中文原因）+ 列表页「重新审查」；回写侧：`app/writeback.py` 失败落 `failed` 并支持重试 |
| 验证方式 | ① 无文本层 PDF 与加密 PDF 两个用例校验状态与原因文案；② 把受阻任务的附件替换为可解析文件后重试，校验转为 completed；③ 注入回写接口故障，校验 `failed` 落库，故障恢复后重试成功 |
| 实测结果 | 07 无文本层 PDF → `blocked`（"未抽取到有效文本层（可能为扫描件或图片型 PDF…）"）；08 加密 PDF → `blocked`（"文档已加密，无法抽取文本，需人工解密后重新上传"）；修正文件后重试 → `completed`，综合风险=高风险，命中 3 项；注入故障后状态=`failed`，恢复后重试状态=`success`（评论标识 `CMT-04-001`） |
| 截图 | `docs/screenshots/05_解析受阻与重试.png` |

> 自检在独立临时目录内执行，不会污染正式审查数据库与已生成报告；
> HTTP 冒烟测试会真实启动服务并发起网络请求，覆盖「服务端 → 模拟审批系统」的跨进程调用链路。

## 四、v1.1 追加能力的验证证据

代码审查后新增/加固的能力，逐项都有对应验证：

| 能力 | 验证项 | 证据 |
| --- | --- | --- |
| 解析阈值真正可配置 | 自检 #22 | 把 `min_text_chars` 调到 100000 后，同一份 PDF 被正确判定为「文本不足」 |
| 上传大小服务端强制 | 自检 #23 + 冒烟 #39 | 2.0 MB 文件在 1 MB 上限下被拒；31 MB 文件返回 400「超过 30 MB 上限」 |
| 文件名路径穿越防护 | 自检 #24 + 冒烟 #40 | `../../../etc/passwd` → `passwd`；`C:\Windows\...\cmd.exe` → `cmd.exe`；上传后文件只落在 `uploads/` |
| 数据更新字段白名单 | 自检 #25 | 传入未登记字段不会拼进 SQL，并写入审计 |
| 规则写坏正则不再静默失效 | 自检 #26 + 冒烟 #43 | 诊断记录 `PU-X-000(regex) → missing ), unterminated subpattern`，详情接口暴露 `rule_diag` |

| 钉钉加签算法正确 | 自检 #28 | 本地假 Webhook 收到请求，URL 含 `timestamp` 与 `sign`，返回 `errcode=0`；消息体为 markdown 且带关键词 |
