## 二、总体架构

系统按"接入 → 解析 → 抽取 → 审查 → 推荐 → 回写 → 展示"七段链路组织，前后端同进程部署，数据落 SQLite。

└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ HTTP / JSON
┌──────────────────────────────────▼───────────────────────────────────────┐
│                     接口层  FastAPI Routers                              │

## 三、技术选型与理由

| 层次 | 选型 | 版本 | 理由 |
| --- | --- | --- | --- |
| Web 框架 | FastAPI + Uvicorn | ≥0.115 / ≥0.32 | 已有技术栈延续，异步、自带 OpenAPI 文档便于讲解 |
| 模板渲染 | Jinja2 | ≥3.1 | 多页服务端渲染，首屏直出，演示环境零白屏 |
| 前端 | 原生 ES Module + 手写 CSS | — | **不依赖任何 CDN**，断网可演示；无构建步骤，交付即可跑 |
| 存储 | SQLite（标准库 sqlite3） | — | 单文件、零运维，便于演示与迁移；足以承载任务状态机与回写日志 |
| DOCX 解析 | python-docx | ≥1.1 | 段落/表格结构完整，可取 run 级文本 |
| PDF 文本 | PyMuPDF (fitz) | ≥1.24 | 抽取速度快，可精确定位字符矩形；同时负责加密检测与页面渲染 |
| PDF 兜底 | pypdf | ≥5.0 | 处理 PyMuPDF 异常文档、加解密探测 |
| 扫描件 OCR | **RapidOCR (onnxruntime)** | ≥1.3 | 纯 pip 安装、**模型随包内置**、无需外部 exe、中文识别效果好；本机 onnxruntime/opencv 已就绪 |
| 图像处理 | Pillow + OpenCV | — | 预处理（灰度、二值化、去噪、倾斜校正）提升 OCR 命中率 |
| 规则引擎 | 自研 YAML 规则 + 受限断言求值 | — | 规则可读可改、非法务也能维护；不使用 `eval` 裸执行，用白名单函数求值 |
| 大模型 | OpenAI 兼容 HTTP 接口（httpx） | — | 与既有项目一致；**默认关闭**，启用后仅用于增强措辞 |
| 报告 PDF | reportlab | ≥4.2 | 注册中文字体后可稳定输出中文 PDF |
| 包管理 | **uv** | 0.12.13 | 项目强制约定 |

### 关键选型决策：LLM 是"增强项"而非"必需项"

演示面向师生，现场网络不可控。因此：

- **规则引擎负责"判定"** —— 高风险/中风险/低风险的结论 100% 由确定性规则产出，可复现、可解释；
- **大模型负责"措辞"** —— 把规则命中的证据链改写成更自然的法律语言，并生成示范条款；
- **自动降级** —— 未配置 API Key 或调用失败时，直接回退到**内置示范条款模板库**，界面提示"规则引擎模式"。

这样即使断网，8 条验收标准中的第 3、5 条依然成立。

## 五、核心数据模型

| 实体 | 关键字段 |
| --- | --- |
| `Contract` | id、文件名、格式(docx/pdf/scanned/pdf_encrypted)、大小、哈希(去重)、来源(审批推送/本地上传) |
| `ReviewTask` | id、contract_id、状态机、回写状态机、风险汇总、阻塞原因、创建/完成时间 |
| `Clause` | id、task_id、条款类型、标题、正文、char_start、char_end、page、para_index |
| `RiskItem` | id、task_id、rule_id、风险等级、风险名称、命中条款、证据片段（含位置）、成因、法律依据、是否采纳 |
| `Suggestion` | id、risk_item_id、示范条款文本、生成来源(rule_engine/llm)、采纳状态、法务修订稿 |
| `Rule` | id、合同类型、审查维度、名称、触发条件、风险等级、依据、建议模板 |
| `WritebackLog` | id、task_id、状态、请求体、响应体、时间、重试次数 |

**溯源坐标系约定（关键）**：以**归一化全文**为唯一定位坐标系。解析阶段将各格式文本统一归一（统一换行、合并软换行、剔除页眉页脚重复行），生成 `full_text`；每个段落记录 `char_start/char_end` 指向 `full_text`，同时记录 `page` 与 `para_index`。前端高亮直接使用 `char_start/char_end` 切分渲染，反向点击高亮片段可回查页码与段号。该约定消除了 DOCX / PDF / OCR 三条链路的坐标差异，是"双向溯源"能成立的前提。

## 六、状态机

```
任务：  pending ──► parsing ──► reviewing ──► completed
                       │            │
                       └──► blocked ◄┘        blocked ──(重试)──► pending
回写：  not_written ──► writing ──► success
                            └─────► failed ──(重试)──► writing
```

阻塞判定：文档加密且无密码 → `blocked/ENCRYPTED`；扫描件 OCR 置信度低于阈值或有效字符数不足 → `blocked/BLURRY`；解析后正文为空 → `blocked/EMPTY_BODY`。

## 七、风险判定规则设计

规则以 YAML 声明，示例：

```yaml
- id: R-PUR-IP-001
  contract_type: 采购
  dimension: 知识产权
  name: 知识产权归属供应商
  level: high
  condition: contains_any(["知识产权归乙方", "知识产权归供应商", "知识产权均归卖方"])
  basis: 《民法典》第八百四十七条、第八百四十三条
  cause: 采购方出资委托开发，成果知识产权应归采购方或双方共有
  suggestion: 因履行本合同所产生的全部成果，其知识产权归甲方所有…
```

判定优先级：**规则命中优先于大模型结论**；两者冲突时以规则为准，并在风险卡标注"规则/模型结论不一致，建议人工复核"。

规则覆盖面（首版）：
- 高风险：主体信息缺失/经营异常、违约责任严重不对等、管辖地约定违规、未设付款前置验收条件
- 中风险：缺少保密义务期限、未明确不可抗力通知时效、违约金比例超法定合理范围
- 低风险：表述不规范、条款编号引用错误、缺失非关键约定项

## 八、前端设计与交互

**风格**：深色专业风（企业级 SaaS 观感），低饱和背景 + 高对比正文，动效克制（仅悬停/切换的 150ms 过渡）。

**风险色板**：高风险 `#E5484D` / 中风险 `#F5A524` / 低风险 `#30A46C`，均配套浅底纹版本用于卡片着色。

**五页职责**

| 页面 | 核心能力 |
| --- | --- |
| 合同审查大盘 | 待审列表（名称/申请人/业务类型/金额/状态/风险等级/时间）、按风险与状态筛选、手动上传入口、状态标签、阻塞重试按钮 |
| 智能审查工作台 | 左栏合同正文（排版分页、风险条款高亮、元数据字段标记）↔ 右栏风险卡片分级列表（成因/依据/示范条款/一键采纳）；点击卡片跳页并定位高亮，点击高亮反向滚动到卡片；下方审批协同回写区（摘要 + 法务批注框 + 一键回写 + 导出报告） |

| 模拟审批系统 | 模拟待办工单 + 评论区，直观展示"审查意见写回"后的效果，用于现场演示 |

## 九、演示设计（面向师生，模拟真实工作场景）

**角色代入**：现场以 `业务经办人` 提交 → 系统自动审查 → 切换到 `法务审查人` 复核采纳 → 一键回写 → 打开模拟审批系统查看评论 → 导出报告。

**剧本（约 8 分钟）**

1. **开场（30s）**：打开大盘，指出这是"法务每天上班第一眼看到的页面"——7 份待审合同，状态与风险等级一目了然。
2. **自动审查（1min）**：点击"拉取审批待办"，`C-2026-001 软件采购合同` 从 `pending → parsing → reviewing → completed` 全流程动画走完，风险等级标红。
3. **溯源定位（2min）**：进入工作台，点"知识产权归属"高风险卡片 → 左栏自动翻到第 4 页并高亮原文；再点"到货即付全款"卡片 → 跳到第 3 页。现场强调：**每个风险都能点回原文，位置精确到字符**。
4. **规则 vs 大模型（1min）**：指出卡片上的法律依据由规则库给出，示范条款由大模型改写（或规则模板生成），说明"结论不靠模型拍脑袋"。
5. **人工复核（1min）**：法务修改示范条款措辞并采纳，录入补充意见。
6. **回写（1.5min）**：点击"写回审批意见"，切到模拟审批系统页面，评论区出现格式化审查意见；回写状态 `writing → success`。
7. **报告与兜底（1.5min）**：导出 PDF 报告；最后演示扫描件 OCR 合同与加密 PDF 触发的 `blocked` 与一键重试。
8. **收尾（30s）**：回到大盘，说明覆盖 8 条验收标准。

## 十、风险与对策

| 风险 | 对策 |
| --- | --- |
| OCR 质量不稳定导致定位偏移 | 图像预处理 + 置信度阈值；低置信度直接 `blocked` 而非硬出结果；OCR 结果以行为段落单位建索引 |
| 三链路坐标不一致 | 统一归一化全文坐标系（见第五节），解析器输出前强制校验 `char_start/char_end` 覆盖完整正文 |
| 大模型不可用 | 规则引擎独立完成判定，模板库兜底措辞，界面明示当前模式 |
| 现场演示网络中断 | 前端零 CDN、OCR 模型本地、LLM 可关，全链路离线可跑 |
| 范围蔓延 | 以会议决议 D-02/D-08 划定边界；真实审批系统联调不在本次范围 |
