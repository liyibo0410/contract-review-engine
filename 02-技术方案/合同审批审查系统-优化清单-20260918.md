### P1-02 归一化全文未剔除页眉页脚

| 项 | 内容 |
| --- | --- |
| **问题** | 技术方案 V1.0 第五节承诺归一化时「剔除页眉页脚重复行」；v1.0 实现了段落树与统一坐标系，但未做页眉页脚剔除 |
| **证据** | 评审意见书 R-07；`app/parsers.py` 无相关处理 |

| **建议动作** | 按页内重复行频率阈值识别并剔除：同一短行在多页（≥2 页）重复出现且位置固定在页首/页尾 → 判定为页眉页脚并剔除；剔除后重算 `char_start/char_end` |
| **验收判据** | 自检新增页眉页脚样例：剔除后噪声段落数为 0，且锚点一致性校验仍全通过 |

### P1-04 无并发与性能保障

| 项 | 内容 |
| --- | --- |
| **问题** | 单机 SQLite 单连接加锁；无解析队列、无资源配额、无性能基准数据 |
| **证据** | SPEC.md 第 10 节「无性能压测」；`app/store.py` 单连接 + `RLock` |
| **影响** | 大批量并发上传时可能出现请求排队；答辩被问"能扛多少"时无数据支撑 |
| **建议动作** | ① 用 `queue.Queue` + 工作线程池实现解析队列（可配置并发数）；② 单文件与总量配额（已有 1 MB 单文件上限，补充总量与队列上限）；③ 产出基准数据：单合同解析耗时、规则引擎耗时（400 段 × 12 规则 = 5 ms 已有）、10 并发拉取表现 |
| **验收判据** | `verify/bench.txt` 产出可复现基准数据；并发上传 10 份不丢任务、不串数据 |
| **目标版本** | v2.0（M10 完成） |

### P1-05 大模型能力未体现价值

| 项 | 内容 |
| --- | --- |
| **问题** | `llm.py` 默认关闭，仅用于中文摘要润色；演示中完全看不到大模型的作用，未体现"规则判定 + 模型措辞"这一双轨设计的优势 |
| **证据** | `config/app.json` 的 `llm.enabled` 默认 false；SPEC 第 3 节 |
| **影响** | 项目主题含"大语言模型"，但交付演示中模型能力不可见，主题贴合度打折 |

| **验收判据** | 工作台提供模式切换与对照视图；断网/无 Key 时自动降级并在界面标注；自检覆盖两种模式 |
| **目标版本** | v2.0（M9 完成） |
