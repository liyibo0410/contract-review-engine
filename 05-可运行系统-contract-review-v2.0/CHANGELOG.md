# 变更日志 · 衡鉴 V2.1.7

本文件遵循 [语义化版本](https://semver.org/lang/zh-CN/)：

- **MAJOR**：出现不兼容的接口或数据模型变更
- **MINOR**：向后兼容的功能新增
- **PATCH**：向后兼容的问题修正

> **版本口径（决议 D-28）**：交付版本 = 运行版本 = 文档版本。
> 版本的唯一真源是 `app/__init__.py` 的 `__version__`；`/api/health`、页脚、报告、
> 演示脚本一律引用它，禁止在其他位置硬编码版本字符串。
> 历史上出现过「前端已 v2.0、`/api/health` 仍报 1.0.0」的版本失真，本文件即该问题的收口产物。
>
> **两套口径（决议 D-43，2026-09-19；2.1.6 修订）**——`__version__` 与品牌名的分工：
> * **技术版本** `__version__`（本文件 + `/api/health.version`）：语义化版本，按 MAJOR.MINOR.PATCH 走；
> * **品牌名** `BRAND_*`（界面顶栏/页脚/报告页脚/评论区/文档标题）：对外名称。
>
> **2.1.6 起品牌版本改为「跟随发布版本」**（当前 = 衡鉴 V2.1.7）。原口径是品牌固定为
> `衡鉴 V2.0.2`、与技术版本解耦；但奕波在界面上看到顶栏还挂着旧版本号，要求「更新到最新版本」。
> 于是：**发一版就把 `BRAND_VERSION` 跟到该版号**，全站一起走。
> 改品牌名的动作仍只有两件事：改 `app/__init__.py` 的 `BRAND_VERSION` + 重跑
> `tools/_onetime/rebrand_hengjian_v202.py`（幂等）。
>
> ⚠️ 该杠杆**刻意跳过 `CHANGELOG.md`**：它是历史记录，把旧条目里的品牌名改成新值等于篡改历史
> （会出现「2.1.4 的品牌收口写成了 2.1.6」这种自相矛盾）。本文件的 H1 标题、版本表与本节口径
> 说明属于**当前口径**，由人工维护；`## [2.1.x]` 各条目里的品牌名保持当时原貌。
>
> 品牌名此前散落在 20+ 个文件里各自硬编码（页脚 `衡鉴 V2.0.2`、报告页脚 `v1.0`、
> `run.py` banner `v1.0`、页面 `<title>` 写 `亦大…`），四套口径互不相同 —— 2.1.4 把它收口到
> `app/__init__.py` 的 `BRAND_*`，并提供幂等脚本 `tools/_onetime/rebrand_hengjian_v202.py`
> 作为**唯一改名杠杆**（再改品牌名只需改常量 + 重跑该脚本）。

## [2.1.7] · 2026-09-19 —— 统计卡金额溢出与竖屏适配

触发：奕波反馈「高风险金额数字过大就会溢出来，而且不适配竖屏」。

先写探针 `tools/probe_overflow.py` 把「溢出」量成数字再动手 —— 它同时暴露了这个问题的真实范围
（**桌面 1600 就在裁**，不是手机专属），以及一个更要紧的东西：验证工具本身的假绿灯（见第四节）。

### 一、金额卡被裁：`overflow: hidden` + 数据驱动的长数字

「高风险金额」是大盘 7 张统计卡里的第 7 张，数值走 `CR.money()`，格式是「完整数字 + 括号万位」：

```
¥1,234,567,890.00 (123456.8 万)      ← 27 个字符
```

卡片是 `.stats` 网格里的 `minmax(170px, 1fr)` 轨道，且 `.stat { overflow: hidden }` ——
金额一大，数字先顶破可用宽度、再被硬切，用户看到的是半截金额。

实测（注入 12.3 亿）：

| 视口 | 卡片宽 | 内容宽 | 溢出 |
| --- | --- | --- | --- |
| 桌面 1600 | 212 | 216 | **38px** |
| 笔记本 1366 | 179 | 216 | **71px** |
| 竖屏平板 1024 | 186 | 216 | **64px** |
| 竖屏平板 820 | 150 | 216 | **100px** |
| 手机竖屏 430 | 199 | 168+31 | **3px**（副标题被挤出卡外） |

### 二、修法：三档降级

金额长度是**数据决定的**（合同金额可能 9,600，也可能 12.3 亿），不能靠固定字号赌：

| 档位 | 手段 | 代码位置 |
| --- | --- | --- |
| ① 降档格式化 | `CR.moneyBrief()`：≥1 亿走「亿」、≥1 万走「万」，长度上界 9 字符（`¥9999.99亿`） | `ui/assets/app.js` |
| ② 自适应字号 | `CR.fitText()` / `CR.fitStats()`：逐级缩字号（步长 0.5px、下限 14px），含 resize 重算 | `ui/assets/app.js` |
| ③ 允许折行 | `.stat.amt .v.wrap` | `ui/assets/app.css` |

**信息不丢**：主显是降档值，精确值退到副标题（`累计 · ¥1,234,567,890.00`）。

### 三、竖屏：导航越界与两处硬切

- 顶栏 4 项导航合计约 440px，430px 屏越界 74px（390px：114px，360px：144px）→
  ≤640px / ≤420px 两档收窄内边距与字号，430px 与 390px 下 4 项可完整落在一行；
- `.env-tag` 被 flex 压窄后内容硬切（`clientWidth 174 < scrollWidth 205`）→ 加省略号；
- 金额卡在 ≤760px **独占整行**（双列时每张卡只有约 150px，放不下）；
- `table.grid td.num` 禁止折行（折行会把「¥4,600,000.00」劈成两行，核对金额时易看错数位）。

### 四、⚠️ 顺带挖出的真问题：`tools/devcheck.py` 是假绿灯

跑回归时发现它的输出路径指向 `D:\workbuddy work\2026-09-19-08-12-06\contract-review-v2.0` ——
不是它所在的目录。核实结果：

- 更糟：脚本**无论内部怎么失败都 `exit=0`**，`run_all.py` 与 CI 都拿不到信号。

已修：`ROOT` 改为从 `__file__` 相对推导（与 `tools/` 下其它脚本一致）+ 新增失败汇总

## [2.1.6] · 2026-09-19 —— 工作台三个交互修复 + 顶栏放大 + 品牌版本跟随

### 一、合同正文卡片「往下滑看不见」—— 根因是 sticky 被 body 的 overflow 废掉

实测（案件 #5，1600×1000）：文档 `scrollHeight=3532`，右栏风险清单 `h=2200`，
而左栏正文卡只有 `h=796`、`top=161` —— **页面滚到 1266px 时正文卡整块滑出视口，可见高度 0**。
也就是说「读右侧风险清单」与「看左侧正文」在滚动上互相排斥。

修法是让左栏贴住顶栏、两栏各自滚动，但改的过程中撞到两个坑：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 加了 `position: sticky` 完全不起作用（各滚动位置仍在随文档上移） | `body { overflow-x: hidden }` —— 按规范，一轴 hidden 会让另一轴的 `visible` 计算成 `auto`，**body 变成滚动容器**，其内部所有 sticky 改为相对 body 的滚动口定位，而真正滚动的是视口 → sticky 全废。**讽刺的是文件第 101 行的注释早就写着这条**，但 body 上仍然留了一份 | `body { overflow-x: clip }`（同样裁掉横向溢出，**不创建滚动容器**） |
| 2 | sticky 生效后仍无移动空间 | 左栏卡片自己就是 grid 项，而 `.wb { align-items: start }` 让列高＝内容高，sticky 无处可移 | 左栏外套一层 `.wb-side`（作为 grid 项被拉伸到整行高），卡片在其内部 sticky |

同时把高度不再写死：原先 `#doc { max-height: calc(100vh - 258px) }`，258 是对页面其余部分
的猜测值，改版一次就失准。改为 flex 分配 + 运行期 `fitDoc()` 实测
（量的是**不参与 sticky 的 `.wb-side` 的文档坐标** —— 直接量 sticky 元素的 `rect.top`
会随滚动位置抖动），并保留一个保守的 CSS 兜底值。

修后实测：**0% / 25% / 50% / 75% / 100% 五个滚动位置，正文卡均为 `top=76, 可见 821/821`（整块可见）**。

### 二、点击风险不跳转 —— `onclick` 丢了

正文里的风险高亮 `<mark>` 带着 `tabindex="0"`、`role="button"`、
`title="点击定位到右侧风险卡片"`，**却没有 `onclick`**；而 `renderDoc()` 里的注释写着
「点击已在 mark 上用内联 onclick 绑定」—— 说明曾经有、后来在清理「重复绑定」时被一起删掉了，
只剩键盘可达性。给 `paraHtml()` 补回 `onclick="pick(id)"`。

顺带修了跳转落点：原来用 `scrollIntoView({block:'nearest'})`，卡片会紧贴视口底、
或在吸顶顶栏下方露出一条边，用户仍看不到要点的那条。改为「未完整可见就居中」，
并给 `.risk-card` 加 `scroll-margin-top: calc(var(--hd) + 18px)` 防止被吸顶顶栏盖住。

修后实测：点正文高亮 → 目标卡片 `.on=true`、滚到视口中央（`top=247`）、
且**左侧正文卡仍 821/821 完整可见**。

### 一、静态资源从 no-store 改为 ETag 条件请求 ⭐ 最大的一项

`_send()` 对所有响应一律发 `Cache-Control: no-store`。对接口和页面这是**刻意的安全口径**
（含登录态与角色信息，不该落盘），但对 `/assets/*` 是纯粹的浪费 ——
浏览器完全不能缓存，**每次翻页都把 CSS/JS/图标重新下一遍**。

实测一次导航请求的静态资源合计 **44.7 KB**（app.css 16.0 + logo 11.5 + app.js 10.8 + fx.css 6.7）。

改法（`app/server.py`）：

| 资源 | 策略 | 依据 |
| --- | --- | --- |
| `/assets/*` | `Cache-Control: no-cache, must-revalidate` + `ETag`（弱校验 `W/"mtime-size"`），命中 `If-None-Match` 回 **304 空响应** | 公开资源，文件名无内容指纹 → 不适合长缓存，但非常适合「存下来、每次问一句」 |
| 页面 HTML | **保持 `no-store`** | 含登录态/角色信息，安全口径不放松 |
| 接口 JSON | **保持 `no-store`** | 实时数据，且不该落盘 |

为什么用 `no-cache` 而不是 `max-age=…`：这些文件名没有内容指纹，长缓存会在**重新部署后
让旧 CSS/JS 粘在浏览器里**，很难向使用者解释；`no-cache` 每次重验证，304 省掉的正是整个
响应体，且永远不会过期失真。若将来要做 `max-age` 长缓存，需要先引入内容指纹（URL 加 `?v=`）。

顺带修掉一个会「静默失效」的写法：`_send()` 原本无条件写 `Cache-Control: no-store`，
若直接把可缓存策略塞进 `extra_headers` 会发出**两个 Cache-Control 头**，
浏览器合并后仍按 `no-store` 处理 —— 现在是 `headers.pop("Cache-Control", None) or "no-store"`。

## [2.1.3] · 2026-09-19 —— 全站卡片动效 + 修复 `.gauge` 类名冲突

触发：先反馈「引擎负载与资源占用还是乱的」，随后「所有页面的全部卡片都做成动态效果」。

### 一、先修一个类名冲突（这才是"还是乱的"根因）

专项探针量出水位框的实际几何：

```
仪表 队列水位  box=68x68  w=68px h=68px flex=0 0 auto overflow=visible
```

`app.css` 里新加的水位框用了 `.gauge`，而 **`fx.css` 里旧的环形仪表也叫 `.gauge`**
（`width:68px; height:68px; flex:none`）。`fx.css` 后加载 → 压过 `app.css`，
于是水位框被压成 **68×68 的小方块**，`overflow: visible` 让里面的标签/数值/进度条/说明
全部溢出，四个方块挤在两列里、右侧空一大片。

→ 新类改名 **`.meter`**（`fx.css` 的 `.gauge` 保持不动，它仍服务于环形仪表场景）。
修复后水位框恢复整列宽度。

> 教训：本项目有**两张样式表**（app.css + fx.css），新增组件类名要先在两处都搜一遍。

### 二、卡片动效系统（全站）

覆盖 8 个页面的全部卡片类：`.panel .card .stat .kpi .tk .kv-cell .risk-card .mode-col
.mock-item .mock-kv .cell .mock-comment .login-card .role-item .deny-card .deny-cell
.meter .pipe-node .sec-item .model-card .store-card`

| 效果 | 说明 |
| --- | --- |
| **入场错峰** | 卡片淡入 + 上移 13px，按序延迟 32ms（最多 14 档），只播一次 |
| **悬停光泽扫过** | 一道极淡的高光沿 105° 斜向扫过（透明度 .055），配边框提亮 |
| **小卡上浮** | ≤3px 位移（大面板只提亮边框 —— 大块位移在栅格里很晃眼） |

| **数值变化脉冲** | 数值变化时跳一下并短暂变青色；**只跳变化的数**，不是整块重播 |
| 表格行悬停 | 行背景轻扫 |

**三条关键设计（都是踩坑后才定下来的）：**

1. **入场只播一次** —— 孪生看板 4 秒刷新一次，若每次重渲染都重播入场，画面会一直抖。
   按「容器」记一次性标记（`container.__cfx`），重渲染不再播；
2. **常驻效果每次都补** —— 页面是动态渲染的，卡片会反复重建。
   若只在首次加类，之后新建的卡片就没有悬停/流光效果；
3. **入动用内联样式写，不靠运行时加类** —— 实测「运行时加 `.cfx-enter` 类 + CSS 命中」
   这条路径不可靠：规则确实在样式表里（CSSOM 可查到 `cfxIn/0.52s`）、类也确实加上了、
   元素也 `matches('.cfx-enter')` 为真，但计算样式仍是 `animation-name: none`。
   改成 JS 直接写 `el.style.animation`，跑完清掉，不残留。

### 三、顺带修的两处

- **悬停扫光改用动画而非过渡**：`.panel` 同时带 `.reveal`，而 `html.js .reveal.in`
  （特异性 0,3,1）的 `transition` 会覆盖 `.cfx`（0,1,0）的 `transition`，
  导致 `background-position` 瞬变、看不到扫过效果。改用 `@keyframes cfxSweep` 动画
  —— 动画不受 transition 覆盖影响。
- **可访问性降级**：`prefers-reduced-motion: reduce` 下关闭入场、流光、扫光与所有过渡。

### 四、新增专用探针 `tools/probe_cfx.py`（9 项）

验证的是**动效真的生效**，而不是"CSS 文件里有这段文字"：

- 浏览器**确实解析到** `.cfx` 规则（读 CSSOM，含规则的 `parentRule`）；
- 加载后 0.3s 能读到 `cfxIn` 动画在跑（7 个）、`cfxBeam` 在跑（5 个）；
- 卡片的计算样式里 `background-image` 是那条渐变（证明规则真的命中）；
- 动画结束后**不留内联样式残留**；
- 孪生看板刷新后 `cfxIn` **不再出现**（证明入场只播一次）；
- 刷新后新建的卡片**仍保有常驻效果**；
- 数值变化检测正确（同值不跳、变值才跳）；
- `prefers-reduced-motion: reduce` 下入场不播、过渡关闭。

### ⭐ 一个重要的环境发现

**headless Chrome 默认就报 `prefers-reduced-motion: reduce`。**
本项目的可访问性降级块里有 `animation: none !important` / `transition: none !important`
（`*` 选择器），于是**全部动效被静默吃掉**，探针一开始显示"动效没实现"，
排查了很久才定位到是环境默认值而不是代码问题。

→ 探针现在**显式声明** `Emulation.setEmulatedMedia(prefers-reduced-motion: no-preference)`

**这条对所有做动效自动化的场景都成立：不显式声明偏好，你测到的是降级路径。**

### 第二轮：信息架构（「还是乱的」）

上一轮只解决了数据对不对，没解决"乱"。真实来源三条：

1. **一个面板塞了三类内容**（运行指标 kv 卡片 + 资源水位仪表 + 能力清单 kv 卡片），

| 面板 | 内容 | 形态 |
| --- | --- | --- |
| 引擎运行指标 | 解析吞吐 / 接口平均与峰值耗时 / 命中密度 / OCR 置信度 / 错误率 / 运行时长 | **一行一项的对齐列表**（标签·数值·说明三列对齐） |

| 接口响应 | 请求量 / 平均 / 错误率 / 响应总量 + 热点接口 + 慢请求 | kv 卡片 |

| 合规机制与规则库 | 规则库构成 + 合规口径 | 规则条 + kv |

布局：中排改三栏（引擎运行指标 ｜ 资源水位与配额 ｜ 接口响应），
底排维持三栏（实时审查日志 ｜ 流转与调度 ｜ 合规机制与规则库）。

排查中发现 `/api/twin` 的 `notify` 字段**全是 null**，进而「脱敏」被显示成 **"关闭"**
（实际全程开启）。根因：

```python
nt = notify_mod.get_notifier(cfg, st)   # ← get_notifier 在 pipeline 里，不在 notify 里
except Exception:
    nstat = {}                          # ← 异常被静默吞掉
```

**同一个错误在 AI 助手的「系统状态」回答里也存在**——它同样把通知说成"未配置"、

- 自检加断言：`errors` 必须为空、`notify.mask.party` 必须为真、
  助手系统状态回答里必须出现「脱敏 已开启」。

## [1.0.0] · 2026-09-18 —— 可演示原型

- 七段链路打通：接入 → 解析 → 抽取 → 审查 → 推荐 → 回写 → 展示；
  前后端同进程、数据落 SQLite，**零运行期第三方依赖**。
- 多格式解析：DOCX（`zipfile` + `xml.etree`）、PDF（自研对象扫描 + `/Filter` 链 + ToUnicode CMap）、
  扫描件 OCR（Windows WinRT / Linux `tesseract` 双后端）。
- 规则引擎 5 种匹配模式（`keyword` / `regex` / `absence` / `pair` / `numeric`），
  4 类合同共 41 条规则；风险判定 100% 由规则产出，大模型仅润色措辞。
