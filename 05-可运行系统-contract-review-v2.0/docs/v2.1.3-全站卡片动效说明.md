# v2.1.3 全站卡片动效说明

- 版本：**2.1.3**（MINOR：新增动效系统，不改接口与数据模型）
- 日期：2026-09-19
- 触发：反馈「**所有页面的全部卡片都做成动态效果**」

这句话里有三处需要被**量化**才能算做到：

| 词 | 潜在的敷衍做法 | 本轮的验收方式 |
| --- | --- | --- |
| **动态效果** | 加个 `transition` 就算 | 专项探针量「浏览器里真的在播哪些动画」 |
| **所有页面** | 只改首页 | 逐页对账，7 个页面一个不漏 |
| **全部卡片** | 「看着都动了」 | 逐页数卡片：总数 vs 已装饰数 |

## 一、动效清单（四层，全部克制）

| 层 | 效果 | 触发时机 | 实现 |
| --- | --- | --- | --- |
| ① 入场 | 淡入 + 上移 13px，**按位置错峰**（每张 +32ms，上限 14 档） | 页面首次加载 | `cfxIn`，JS 写**内联** `animation` |
| ② 悬停 | 一层斜向光泽扫过 + 边框提亮 + 外发光 | `:hover` | `cfxSweep`，用 **animation** 而非 transition |
| ③ 上浮 | 小卡片上移 3px；大面板**只提亮边框** | `:hover` | `.cfx-lift` |
| ④ 强调条 | 卡片左侧的强调条上有一道光缓缓流过 | 常驻循环 | `cfxBeam`，5.4s 线性无限 |
| ⑤ 数值 | 只有**变化的那个数**跳一下 | 定时刷新 | `cfxTick`，由 `CR.motion.changed()` 判定 |

### 三条硬约束（这是「克制」的具体含义）

1. **入场只播一次** —— 孪生看板每 4 秒刷新一次，若每次刷新都重播入场，
   页面会永远在"呼吸"，非常干扰。做法是按容器打标记（`__cfx`），
   **刷新重建的节点只补常驻效果、不重播入场**。
2. **动画只负责运动，终态由 CSS 决定** —— 动画被禁用（`prefers-reduced-motion`、
   老浏览器、CSS 加载失败）时，卡片必须是**完全可见**的，不能停在 `opacity:0`。
   所以入场动画写的是 `both` + 起始态由 keyframe 提供，而不是把元素初始设成隐藏。
3. **降级必须真的降级** —— `prefers-reduced-motion: reduce` 下：无入场、无流光、
   无光泽扫过、无位移，只保留颜色变化。

### 大面板 vs 小卡片

大块位移在栅格里非常晃眼，所以**分两档**：

```
小卡片（.stat/.tk/.kv-cell/.risk-card/.mock-item/.meter/…）→ 上浮 3px
大面板（.panel/.card/.deny-card）                        → 不动，只提亮边框
```

## 二、踩的四个坑（都值得记下来）

### 坑 1：`.gauge` 类名冲突 —— 这才是「引擎负载还是乱的」真正根因

孪生看板新加的水位框类名叫 `.gauge`，而 `fx.css` 里**旧的环形仪表也叫 `.gauge`**
（`width:68px; height:68px`）。`fx.css` 后加载，把水位框压成 **68×68 小方块**，
里面的标签/数值/进度条/说明**全部溢出**出来，四个方块挤在两列里、右边空一大片。

```
量到的实况：仪表 队列水位  box=68x68  w=68px h=68px  overflow=visible
```

**教训**：改 CSS 前先 `grep` 一下类名有没有被别处用过。新类已改名为 `.meter`。

### 坑 2：加了类、规则也解析到了，计算样式却是 `animation-name: none`

`document.styleSheets` 里能读到 `.cfx-enter { animation: cfxIn … }`，
类也加上了，但元素的计算样式就是 `none`。

**根因不在 CSS，在测试环境**：headless Chrome 默认 `prefers-reduced-motion: reduce`，
而我的降级块里有 `animation: none !important` / `background-image: none !important`
—— **动效一直被降级规则吃掉**，测的是"降级后的样子"。

修法：探针里显式声明偏好 `Emulation.setEmulatedMedia{prefers-reduced-motion: no-preference}`，
同时保留一项**专门测降级**的检查（在同一浏览器里模拟 `reduce` 再断言动画数为 0）。

```
修复前：cfxIn × 0 ｜ 卡片 background-image: none
修复后：cfxIn × 7 ｜ cfxBeam × 5 ｜ 卡片背景 = linear-gradient(...)
```

**教训**：任何「配置对了但不生效」的怪事，先怀疑**环境注入的隐式偏好**。

### 坑 3：`.panel` 同时是 `.reveal`，光泽扫过被更高特异性的 transition 盖掉

`html.js .reveal.in { transition: … }` 的特异性高于 `.cfx { transition: … }`，
于是光泽扫过没起来。

**修法**：把扫光从 transition 改为 **hover animation**（`cfxSweep`）——
动画不受 transition 覆盖影响。

### 坑 4：`__cfx` 一次性标记在 `DOMContentLoaded` 就被消耗掉了

最初把「是否已播放入场」的标记打在**容器**上，`DOMContentLoaded` 时就用掉了；
此后页面**异步渲染出来的卡片**（大盘的 kv-cell、模拟审批页重建的列表）
永远不会被装饰。

**修法**：拆成两件事 ——
**常驻效果每次都补**（幂等，用元素级标记 `el.__cfx` 去重）；
**入场只播一次**（容器级标记）。

## 三、覆盖率对账：一次抓出 3 处真遗漏

`probe_cfx.py` 只证明「机制在工作」，**没有证明「每张卡片都挂上了」**。
新增 `tools/probe_cfx_coverage.py` 逐页数，第一次跑就漏了 3 处：

| 页面 | 遗漏 | 根因 |
| --- | --- | --- |
| 审查大盘 | 6 个 `.kv-cell` | 在 `loadSched()` / `loadQueue()` 里**异步渲染**，晚于入场调用 |
| 模拟审批系统 | 8 个 `.mock-item` | 点选时 `renderList()` **重建了节点** |
| **越权拦截页** | 整页 5 张卡片 | `denied.html` 是自包含页，**根本没引 `app.js`** |

### 前两处：改用 `MutationObserver` 兜底

「在每个渲染点手调一次」注定漏（新增一处渲染就漏一处）。改成任何新插入的
节点只要命中卡片选择器就补装饰 —— **只装饰、不重播入场**。

### 第三处：页面级遗漏

`denied.html` 补引 `/assets/app.js`。引入前核对了安全性：

- `app.js` 初始化全程**防御式**：`#themeBtn` 缺失即返回、不调任何接口；
- `mountDecor()` 追加的 `.glow` / `.scanline` 都是 `position:fixed`，
  **不参与 flex 布局**，不会把页面里 flex 居中的 `.deny-card` 挤偏
  （登录页同款结构已验证可行）。

### 结果

```
对账前：4 / 6 个页面全覆盖（98 张卡片里 14 张没挂动效）
对账后：7 / 7 个页面全覆盖（103 张卡片全部装饰）

审查大盘 25 ｜ 智能审查工作台 11 ｜ 合规规则与模板 5 ｜ 动态孪生看板 32
模拟审批系统 20 ｜ 登录页 5 ｜ 越权拦截页 5
```

### 探针自身的一个防伪设计

越权拦截页必须用「**确实没有该能力**」的角色访问受限页才会出现，
所以探针单独取一个业务经办人会话去访问 `/rules`，并**断言 `.deny-card` 存在**、
同时记录实际落点（`location.pathname` + `document.title`）——
否则页面被重定向到别处后，「有卡片」会**假通过**。
