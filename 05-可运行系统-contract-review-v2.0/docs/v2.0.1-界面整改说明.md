## 二、孪生看板：从「造数」到「对账」（这是最重要的一条）

### 之前是什么样

```js
let load1 = 62, load2 = 38, load3 = 24;              // 硬编码
function driftGauges() { load1 += Math.random()*4 - 2; }   // 随机漂移
function tickPipeline() { /* 随机点亮节点 */ }
function buildLog() { return 模板 + Math.random().toString(16).slice(2,10); }  // 假指纹
```

页面底部甚至写着「演示态模拟值」。这在审计上是站不住的：
**看板存在的意义就是反映真实运行状态，一旦掺入模拟值，它会主动误导判断。**

### 现在是什么样

新增服务端 `GET /api/twin`，一次性聚合；前端只负责展示，不做任何插值：

| 看板区块 | 数据来源 | 校验方式 |
| --- | --- | --- |
| 流水线①审批接入 | `contract_cases` 计数（按 `source` 拆审批/上传） | 与 `/api/cases` 条数一致 |
| 流水线②文档解析 | `contract_documents` 页/段/字符 + 受阻数 | 与案件状态一致 |
| 流水线③条款抽取 | `data/parsed/case_*.json` 的 `clauses` 与 `stripped` | 逐份快照求和 |
| 流水线④规则审查 | `review_results` 命中数 + 规则库实际加载条数 | 与逐行统计一致 |
| 流水线⑤条款推荐 | `review_results.adopted` + 条款词典/示范条款库规模 | 与逐行统计一致 |
| 流水线⑥意见回写 | `writeback_logs` 成功数 / 尝试数 | 与案件回写状态一致 |
| 流水线⑦报告产出 | `data/reports/` 实际文件数 | 目录列举 |
| 仪表 | 队列水位 / 待处理堆积 / 附件存储 / OCR 平均置信度 | 真实阈值（50 / 40 / 2048MB / 50%） |
| **实时审查日志** | **`audit_logs` 直接读取** | 首条 id 与 `/api/audit` 对齐 |
| 合规机制 | 脱敏开关、事件收敛、越权拦截次数 | 取自运行时配置与计数 |

**每个流水线节点下方都标注了数据来源表/目录**，便于逐项复核。
刷新间隔 4 秒，新日志条目进入时整行高亮（`fresh` 动画）—— 这是真实的「实时」，
不是动画效果。

### 怎么验证它不造假

`tools/check_twin_data.py`（已并入 `tools/run_all.py`）：

* 把聚合结果与**逐行统计**对账（任务数、命中数、采纳数、回写成功数、金额分档全部比对）；
* 断言载荷不含 `random` / `simulated` / `fake` 等字样；
* 断言每个流水线节点都带 `src` 字段；
* 断言 `/api/twin` 的必需键齐全（这条是踩过坑补上的：漏了 `http` 键导致页面整块不渲染）。

`verify_remote_v2.py` 在公网上再做一次交叉验证：twin 的总任务数必须等于 `/api/cases`
的条数、twin 首条日志 id 必须等于 `/api/audit` 的首条 id。

## 三、统计卡下钻：口径与大盘严格一致

7 张卡各自对应一个查询：

| 卡片 | 下钻查询 |
| --- | --- |
| 审查任务总数 | `/api/cases`（无筛选） |
| 高风险合同 | `/api/cases?risk=high` |
| 中风险合同 | `/api/cases?risk=medium` |
| 审查完成 | `/api/cases?status=completed` |
| 解析受阻 | `/api/cases?status=blocked` |
| 回写成功 | `/api/cases?writeback=success` ← 本次新增的筛选参数 |
| 高风险金额 | `/api/cases?risk=high`（按金额合计与单笔最高展开） |

弹窗内容：**汇总条**（命中任务数、金额合计、单笔最高、涉及相对方数、占全部任务比例）
+ **明细表**（单号 / 名称 / 相对方 / 金额 / 风险 / 审查状态 / 回写 / 操作）。
点任一行进入该任务的审查工作台，另有「在大盘中按此条件筛选」一键回填筛选器 ——
**弹窗里的数就是列表里的数**，不做前端本地过滤，避免两处口径漂移。

可访问性：卡片是 `role="button"` + `tabindex="0"`，Tab 聚焦、Enter/空格打开。

## 四、模拟审批系统：从裸 JSON 到查看页

* 新增 `/mock`（需登录）：左侧待办单列表（可搜索）、右侧详情（含本系统处理结果与
  **真实评论区**）、模拟平台对外接口清单、底部可展开的「原始 JSON 响应」。
* 默认选中**有评论的那张单**，打开就能看到本系统写回的审查意见。
* **对外契约不变**：`/mock/feishu/api/*` 仍匿名可调、仍返回原始 JSON（巡检里有专门断言）。
  这一条很重要 —— 模拟平台是「外部系统」，它的接口不能因为本系统要好看就被改掉。
* `/mock/` 不再整体匿名开放：只放行 `/mock/feishu/api` 这个前缀，`/mock` 页本身需要登录
  （页面里含合同名称与金额）。

## 八、遗留说明（如实列出）

1. **视觉细节最终由人确认**。自动化能验证「元素渲染出来了、数字对得上」，
   但「好不好看」只有你能判断。请直接看 `docs/screenshots/` 里的 13 张图，
   尤其是 `07/08` 两张手机端与 `01/04` 两张改动最大的页面。
2. **线上 8 个案件的解析快照仍是 v2.0 审查产生的**，因此它们的
   `mode_compare` / `stripped` 字段为空（孪生看板上的「剔除页眉页脚 0 行」就是这个原因，
   不是功能失效）。在任意案件上点一次「重新审查」即会生成新版快照。
3. 孪生看板刷新间隔 4 秒。若需要更快，改 `ui/twin.html` 里的 `setInterval(refresh, 4000)`
   即可；不建议低于 1 秒（聚合本身约 70ms，且会推高审计表读写）。
