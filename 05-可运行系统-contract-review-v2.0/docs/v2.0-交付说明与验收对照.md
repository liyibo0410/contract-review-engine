## 一、本次交付解决了什么

第二次扩大会议审计出 **D-16（需求 2.4.2 角色权限）是唯一未执行业务决议**，
并点出三个高风险项：**通知外发合同敏感信息**、**版本号失真**、以及
**技术栈红线第三次复发**。v2.0 把这四项连带实现到位：

| 会议决议 | 要求 | v2.0 实现 |
| --- | --- | --- |
| **D-16 / D-27** | 需求 2.4.2 三角色权限闭环（唯一未执行的 P0） | `app/auth.py` + `ui/login.html` + `ui/denied.html`，路由级权限表，越权 403 并留痕 → **需求 2.4 条目 10 / 10** |
| **D-28** | CHANGELOG 与语义化版本；`/api/health` 返回真实版本号；禁止版本失真 | `CHANGELOG.md`；`app/__init__.py` 为版本唯一真源；自检内含「交付=运行=文档」断言 |
| **D-29 / D-30** | 技术方案 V2.0 冻结；前端改版回写方案、说明 4 页面与 2.4.3 的映射 | 见本文第三章「页面与需求映射」 |
| **D-31** | 通知外发脱敏 + 事件默认收敛，未完成不计入交付 | 字段级掩码 + 整段兜底扫描；`batch_summary` / `review_completed` 默认关闭 |
| **D-32** | 对标批次不得引入第三方运行期依赖 | 本次全部新增模块**零第三方依赖**（含 PDF 直出、队列、调度、鉴权） |
| **D-39** | M8 → M9 → M10 → M11 串行推进 | 本次一次性推进至 M10，验证见第五章 |
| **D-40** | 规则/模型模式对照必须可演示；PDF 演示口径；演示工程五项兜底 | 工作台模式对照面板；服务端 PDF 直出 + 三通道降级；演示兜底见第四章 |
