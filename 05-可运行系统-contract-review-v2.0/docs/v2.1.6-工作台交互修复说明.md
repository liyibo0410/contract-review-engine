## 一、合同正文卡片「往下滑看不见」—— 根因是 sticky 被 body 的 overflow 废掉

### 量的结果（案件 #5，1600×1000）

```
文档 scrollHeight = 3532        右栏风险清单 h = 2200
左栏正文卡  h = 796, top = 161  ← 页面滚到 1266px 时整块滑出视口，可见高度 0
#doc 内层滚动区  内容 1724 / 窗口 742
```

也就是说「读右侧风险清单」与「看左侧正文」在滚动上**互相排斥**：想读风险就得放弃正文。

### 修的过程撞到两个坑

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 加了 `position: sticky` **完全不起作用**（各滚动位置仍在随文档上移） | `body { overflow-x: hidden }` —— 按规范，一轴 `hidden` 会让另一轴的 `visible` **计算成 `auto`**，于是 **body 变成滚动容器**，其内部所有 sticky 改为相对 body 的滚动口定位；而真正滚动的是视口 → sticky 全废。<br>**文件第 101 行的注释早就写着这条**，但 body 上仍然留了一份 |
| 2 | sticky 生效后仍**没有移动空间** | 左栏卡片自己就是 grid 项，而 `.wb { align-items: start }` 让列高＝内容高 → sticky 无处可移 |

### 改法

```css
/* 1) 用 clip 而不是 hidden：同样裁掉横向溢出，但不创建滚动容器 */
body { overflow-x: clip; }

/* 2) 左栏外套一层 .wb-side（作为 grid 项被拉伸到整行高），卡片在其内部 sticky */
.wb-side > .panel {
  position: sticky; top: calc(var(--hd) + 14px);
  display: flex; flex-direction: column;
}
.wb-side > .panel > .doc-scroll { flex: 1 1 auto; }
```

**高度不再写死**：原先 `#doc { max-height: calc(100vh - 258px) }`，258 是对页面其余部分的
猜测值，改版一次就失准（这次卡片底部就会被视口裁掉）。改为 flex 分配 + 运行期
`fitDoc()` 实测，并保留一个保守的 CSS 兜底值。

```js
// 注意：**不能**直接量卡片的 rect.top —— 卡片自己是 sticky，其 top 会随滚动位置变化
// （吸附后恒为 76），据此算高度会随滚动抖动。
// 改为量不参与 sticky 的 .wb-side 的**文档坐标**，它与滚动无关、且偏保守。
function fitDoc() {
  const p = document.querySelector('.wb-side > .panel');
  const side = document.querySelector('.wb-side');
  if (!p || !side) return;
  if (getComputedStyle(p).position !== 'sticky') { p.style.maxHeight = ''; return; }
  const hd = parseFloat(getComputedStyle(document.documentElement)
    .getPropertyValue('--hd')) || 62;
  const restTop = side.getBoundingClientRect().top + window.scrollY;
  p.style.maxHeight = Math.max(280, Math.round(innerHeight - Math.max(restTop, hd + 14) - 16)) + 'px';
}
```

单栏（≤1180）与打印时关掉 sticky（否则正文卡会一直压在风险清单上方）。

## 二、点击风险不跳转 —— `onclick` 丢了

正文里的风险高亮 `<mark>` 带着 `tabindex="0"`、`role="button"`、
`title="点击定位到右侧风险卡片"`，**却没有 `onclick`**。

而 `renderDoc()` 里的注释写着「点击已在 mark 上用内联 onclick 绑定」——说明这个绑定曾经存在，
后来在清理「重复绑定导致触发两次」时被一起删掉了，只留下键盘可达性（Enter/Space 还能用，
鼠标点了没反应），所以肉眼与人工测试都不容易发现。

**修法**：给 `paraHtml()` 补回 `onclick="pick(id)"`（只留这一处绑定，避免双触发）。

顺带修了**跳转落点**：原来用 `scrollIntoView({block:'nearest'})`，卡片会紧贴视口底边、
或在吸顶顶栏下方只露出一条边，用户仍然看不到要点的那条。改为「未完整可见就居中」，
并给 `.risk-card` 加 `scroll-margin-top: calc(var(--hd) + 18px)` 防止被吸顶顶栏盖住。

### 修后实测

```
点正文第 1 个高亮（data-rid=6，文本「试用期为 9 个月」）
  → 目标卡片 .on=true ｜ top=247 bottom=808（居中）
  → 页面 scrollY=594 ｜ 左侧正文卡仍 821/821 完整可见
```
