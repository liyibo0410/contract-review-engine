## 一、先解决"怎么发现问题"

肉眼看不出的前端问题（布局塌陷、元素重叠、横向溢出、脚本静默报错）
在 `--dump-dom` 里是看不见的 —— 它只能给 HTML 结构，量不出几何。

于是补了三样东西：

| 工具 | 作用 |
| --- | --- |
| `tools/cdp.py` | **零依赖的极简 Chrome DevTools Protocol 客户端**（手写 WebSocket：握手 + 客户端掩码文本帧 + 分片长度解析）。有了它才能在真实浏览器里执行 JS 并取回布局数据 |
| `tools/audit_frontend.py` | 六页逐个跑，查 8 个维度：脚本异常 / console 错误 / 空容器 / 元素塌陷 / 重复 id / 模板占位符残留 / 横向溢出 / 顶栏重叠 |
| `tools/audit_interactive.py` | 查「点开之后」的状态：下钻弹窗、助手面板、引导气泡与聚光灯、工作台卡片→正文定位、模拟审批页详情 |
| `ui/assets/pet.js` 的错误哨兵 | 把 `window.onerror` / `unhandledrejection` 写进隐藏节点 `#petErrLog` —— 让「页面某块空着」这种静默失败变成**可断言的事实** |

这两套体检已并入 `python tools/run_all.py`（`front` / `inter`）。

## 二、体检发现的真实问题（6 项）

### 1. 顶栏在 1600px 桌面宽度下就换成了两行 ⭐ 最主要的问题

实测顶栏高 **94px**（两行）。根因：

```
a.brand       w=279
nav.nav       w=429
span#envTag   w=612   ← 元凶
a.btn(模拟审批) w=117
button(主题)   w=67
```

环境标签宽 **612px** —— 因为它把审批通道、OCR 后端、PDF 通道、版本号全塞了进去：

```
演示环境 · http://127.0.0.1:8160/mock/feishu/api · OCR ocr-tesseract · PDF 标准库直出 · v2.1.0
```

279+429+612+117+67 + 间距 ≈ 1550，再算上内边距就溢出了 1600，按钮被挤到第二行，
顶栏下方还留着大片空白。

**这是 2.0.1 改 `min-height + flex-wrap` 时引入的回归。**

修法：
- 环境标签只留 `演示环境 · v2.1.0`（`max-width:176px` + 省略号），完整信息移入 `title`；
- 给顶栏定一条**确定性的收放阶梯**，不再出现「按钮跳第二行又留一片空白」：

| 视口 | 行为 | 实测顶栏高 |
| --- | --- | --- |
| ≥1440px | 全部显示，**一行** | 62px |
| 1180–1439px | 收起「模拟审批系统」链接与环境标签，**一行** | 62px |
| <1180px | 允许换行（品牌+角色一行、导航第二行） | 99px |
| ≤640px | 再收起角色文字 chip | 96px（两行） |
| ≤560px | 主题切换只留图标（不隐藏功能，40px） | 96px |

### 2. 981~1280px 区间按钮跨行跳位

`hide-sm` 只在 ≤980 生效，中间地带布局凌乱（实测 7 个块散在 7 个 y 坐标上）。
→ 统一改为按阶梯收放（`hide-md` / `env-tag` / `compact-xs`）。

### 3. 手机端（390px）顶栏占三行、131px

品牌 146 + 角色区 230 = 376 > 可用 366，差 10px 就掉行。
→ ≤640 隐藏角色文字 chip（下拉框本身就显示角色名）；≤560 主题切换只留图标。
现在 390px = **96px 两行**，主题切换仍可用。

> 踩坑记录：`.compact-xs { font-size: 0 }` 一开始不生效 —— 被 `.btn.sm` 的
> `font-size` 压过去了（特异性 `.btn.sm` = (0,2,0) > `.compact-xs` = (0,1,0)）。
> 必须写成 `.btn.compact-xs`。

### 4. 手机端新手引导气泡遮住要高亮的区域 ⭐

实测：390×844 下首步目标 `#stats` 高 **930px**（7 张卡竖排），
`scrollIntoView({block:'center'})` 把顶部推到视口外（y=**-43**），
聚光灯又整块罩住，气泡没地方放，压在目标上。

修法：
- 目标高于视口 70% 时改用 `block:'start'`（从头看起，而不是居中后顶出去）；
- **聚光灯高度封顶到视口的 45%**，从目标顶部开始罩 —— 既指得清位置，又给气泡留出空间；
- 气泡定位改为基于**聚光灯矩形**，并保证不超出视口。

修后实测：390px 聚光灯 `y=1..395`（封顶 394），气泡 `y=400..608`，**不压高亮区**。

> 顺带修正了体检脚本自己的判据：原来拿「目标元素整体」比对，
> 于是气泡压住元素就算失败 —— 但 tooltip 压住元素本身是正常的，
> **压住高亮区才是问题**。判据改为比对聚光灯矩形。

### 5. 「查看明细 →」浮在统计卡底部空白里

统计卡在网格里会被拉伸到行高（实测 176px），`.x` 副标题结束处距卡片底还有 64px，
提示文字浮在那片空白里，看着像没排好。
→ 移到卡片右上角与标题同行，`.k` 预留右侧空间；同时收紧卡片内部节奏。

### 6. AI 助手首次进入自动弹窗盖住页面

2.1.0 里会在首次进入 1.4s 后自动展开对话面板 —— 面板 392×481 会盖住页面内容。
→ 改为**不主动弹窗**：只在宠物上方飘一句提示（7 秒后收起）+ 加一个小红点，
用户点了才展开。需要直接展开时走深链 `?pet=open`。

## 四、遗留与如实说明

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **"好不好看"仍需人判断** | 自动化能证明「没有重叠/溢出/报错」，证明不了审美。请重点看 `docs/screenshots/01_审查大盘.png` 与 `07/10` 两张手机端 |
| 2 | 手机端顶栏是两行（96px） | 平板/手机上一次放不下品牌+导航+角色+主题，两行是可接受的折中；若希望更矮，可再收导航为汉堡菜单 |
| 3 | 统计卡在窄屏仍是网格拉伸等高 | 同一行卡片等高是常见做法；若希望各卡自适应高度可改 `.stats{align-items:start}` |
| 4 | CDP 体检耗时较长（约 1 分钟） | 两个体检各要起 6~8 个浏览器标签页；已并入 run_all，日常可单独跑 |
