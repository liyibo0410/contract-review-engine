## 一、它是什么

一个随页面悬浮的助手：**随时问、随手带**。

| 能力 | 说明 |
| --- | --- |
| 悬浮宠物 | 右下角常驻，可拖到任意位置（左右吸附并记忆），点击展开对话 |
| 对话问答 | 问流程、问操作、问权限、问安全，也能问**实时数据**（现在有多少任务、某份合同有哪些风险） |
| 新手引导 | 点「引导」→ 聚光灯高亮真实按钮 + 气泡说明，**一步一步教到点上** |
| 角色感知 | 每一步会标注当前角色能不能做；做不了的可以**一键切身份后继续** |

入口有三个：点宠物、页面上任何地方按 `Esc` 关闭、以及深链参数
`?pet=open`（直接开对话）/ `?pet=tour`（直接开引导）。

## 二、设计口径（三条硬约束）

### 1. 能确定回答的，绝不交给模型

和「规则引擎判定风险、模型只改措辞」是同一套口径：

* **事实**（任务数、风险等级、规则命中、权限边界、系统状态）→ 确定性代码从真实数据里查；
* **大模型**（若配置了 `llm.enabled`）→ 只在**已确定的事实之上改写措辞**，
  系统提示词明确写「不得新增系统不具备的功能、不得编造数据或规则」；
* 未配置 Key → 用内置模板，功能不缺失。

> 这与工作台的「审查表达模式对照」是同一个原则的两次应用。

### 2. 不知道就说不知道

匹配不到时的回答是固定的：

> 没匹配到我能确定回答的问题，所以我不猜。
> 我能准确回答这几类：流程与原理 / 操作指引 / 权限 / 实时数据 / 系统状态……

**这条比"看起来更聪明"重要**：一个会编造"规则第 7.2 条规定了…"的助手，
在法务场景里是负资产。

### 3. 助手只读，不做任何审批动作

`app/assistant.py` 内**不存在** `update_case` / `add_results` / `writeback.send` 之类的调用
（自检里有专门断言）。助手不能采纳建议、不能回写、不能改规则 —— 
这些必须由人在界面上完成，权限由服务端校验。助手只负责**回答**与**指路**。

## 三、新手引导是怎么"教到点上"的

### 步骤定义（服务端）

每一步包含：目标选择器、标题、说明、所需能力、推进方式。

```python
{"id": "dash-pull", "target": "#btnPull", "cap": "pull_todo",
 "title": "第 1 步：拉取待办并审查",
 "desc": "点这个按钮，系统会把审批平台里的待审合同拉进来…",
 "advance": "click"}
```

6 个页面共 **26 步**（首页 7 / 工作台 7 / 规则页 3 / 孪生看板 4 / 模拟审批 3 / 登录页 2）。

### 三种推进方式

| `advance` | 行为 |
| --- | --- |
| `click` | **必须真的点中目标元素才前进** —— 这是「教用户怎么点」的落点。点错不前进，不会糊弄过去 |
| `next` | 点「下一步」即可（用于"看这里"这类讲解型步骤） |

### 角色感知

当前角色没有该步骤所需能力时，气泡里会写清「这一步需要『回写审批意见』权限，归属：法务审查人」，
并给一个 **「切换为法务审查人」** 按钮；点了会切身份并**回到原页面、从原步骤继续**
（状态存在 `sessionStorage`）。

> 实测：工作台 7 步在法务视角全部可做；切到业务经办人视角，有 4 步被标为受限。
> 引导本身就是权限边界的可视化。

### 每一步都指向真实存在的元素

这是最容易出问题的地方（写了选择器但页面上没有这个元素），所以做了**两层断言**：

1. `tools/check_assistant.py`（静态）：
   - 把选择器拆成 `id="x"` / `class="x` / `attr="v"` 锚点，逐个在对应页面源码里搜；
   - 对**JS 渲染后**才存在的元素（风险卡片、规则行等 6 步）标记 `dynamic: true`，
     退化为「生成器里仍产出这个锚点吗」；
   - 额外断言**选择器是合法 CSS** —— 这条是踩过坑补的：最初写了 `#card-\d+` 这种
     正则形态，`querySelector` 会直接抛错，引导在那一页就废了。
2. `tools/verify_render.py`（浏览器）：
   真的用无头浏览器打开 `/?pet=tour`，断言聚光灯、气泡、进度、按钮都在 DOM 里。

## 四、能回答什么（举例）

| 类型 | 示例问法 | 数据来源 |
| --- | --- | --- |
| 流程 | 「审查流程分几步？」 | 内置知识库 |
| 操作 | 「怎么把审查意见写回审批单？」 | 内置知识库 + 跳转/引导动作 |
| 权限 | 「我是谁？我能做什么？」「为什么这个按钮是灰的？」 | `auth.CAPS` 实时计算 |
| 实时 | 「现在一共有多少个审查任务」 | `store.stats()` + `rollup()` |
| 个案 | 「《XX采购合同》有哪些风险」 | 按关键词定位案件 → `review_results` |
| 规则 | 「PU-H-001 这条规则是什么」 | `config/rules/*.json` |
| 状态 | 「系统现在运行状态怎么样」 | 队列 / 调度 / PDF 通道 / 通知，实时读 |

登录页没有会话，用**内置的游客小知识库**（4 条，只讲登录与身份），并明确告知
「登录后我就能带你走整套流程」。

## 六、演示时怎么用（建议加进讲解）

1. **开场就用它**：打开首页 → 宠物自动邀请 → 「带你走一遍」→ 7 步走完首页主要操作
   （比人工讲一遍更稳，也不会漏）；
2. **权限边界用引导演示**：切到业务经办人 → 在工作台起引导 →
   到「采纳建议」那步会说需要法务权限并给出切换按钮 → 点它 → 身份切换后**自动回到原步骤**；
3. **用提问展示"它不编"**：当面问一个它不知道的问题（如「明年棉花期货会涨吗」），
   看它明确说不知道并给出可答方向 —— 这比夸它聪明更有说服力；
4. **实时数据问答**：问「现在有多少个审查任务」「《XX合同》有哪些风险」，
   答案与大盘/工作台完全一致。

## 七、已知限制（如实列出）

| # | 限制 | 说明 |
| --- | --- | --- |
| 1 | 引导步骤是**预定义**的 26 步 | 不是模型现场生成路径；新增页面需同步加步骤（自检会提醒选择器失效） |
| 2 | 助手不做多轮上下文推理 | 每问独立匹配，回答里会带上一步的上下文提示，但不做真正的会话记忆 |
| 3 | 宠物位置只记左右停靠 | 不记任意坐标，避免在不同分辨率下跑到屏幕外 |
| 4 | 登录页的问答是内置的 4 条 | 没有会话就没有接口权限，只能答登录相关 |
| 5 | 助手回答写审计 | 每次 `assistant.ask` 都会落一条审计；高频提问会让审计表增长较快 |
