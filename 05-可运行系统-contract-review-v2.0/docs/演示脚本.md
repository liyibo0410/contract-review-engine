# 端到端演示脚本 · v2.0（三角色分段版）

用于项目演示与验收答辩。**v2.0 起演示按角色分段**：法务审查人 / 业务经办人 / 系统管理员
各走自己那段权限内的事，中间用顶栏的身份切换串起来 —— 这样「权限边界」不是嘴上说的，
而是当场做出来的。

## 演示前 60 秒准备

```bash
python tools/reset_data.py        # 回到干净状态（清库 + 重置模拟审批）
python run.py                     # 默认 http://127.0.0.1:8770
```

打开 `http://127.0.0.1:8770/` —— **会先跳到登录页**，这就是第一个演示点。

| 演示账号 | 口令 | 角色 |
| --- | --- | --- |
| `applicant` | `Apply@2026` | 业务经办人 |
| `legal` | `Legal@2026` | 法务审查人 |
| `admin` | `Admin@2026` | 系统管理员 |

> 演示时可直接用登录页的 **「一键进入」** 或顶栏的身份切换，不必现场输口令；
> 但**建议第 0 段用真实口令登录一次**，因为「口令是哈希存储、Cookie 是 HttpOnly」这件事
> 值得在演示里说出来（自检里有一条专门断言它）。

演示总时长约 12～14 分钟（精简版 5 分钟见文末）。

---

## 第 0 段 · 开场与登录（1 分钟）

**操作**：打开 `/`，被跳到登录页。

**讲解**：

> 「先看这个跳转。需求 2.4.2 要求三类角色分工，所以未登录访客进不去任何页面和接口。
> 现场登录一次。」（用 `applicant` / `Apply@2026` 登录）

登录成功后可在大盘点 **「角色与权限」** 打开能力矩阵：

> 「权限不是按角色硬编码在页面里的，而是一条『路由 → 能力 → 角色』的表，
> 集中在 `app/auth.py`。前端只负责显隐按钮，**真正的拦截全部在服务端** ——
> 手工构造请求照样会被 403 拦下，而且会写审计。这个我们最后会用反例验证一次。」

---

## 第 1 段 · 业务经办人：送审与自查（3 分钟）

**身份**：业务经办人（`applicant`）

**操作 1**：点右上角 **「拉取待办并审查」**。

> 「对应『审批触发』：系统按频率拉取待办审批单，按审批单唯一标识建任务。
> 这一步是**审批系统主动推过来的合同**。」

8 个任务在几秒内变为「审查完成」，出现高风险红色标签。

**操作 2**：**再点一次「拉取待办并审查」**。

> 「第二次 8 个全部跳过。除了审批单号，系统还对附件算 SHA256 指纹，
> 同一份文档不会被重复解析 —— 这是第二层幂等。」
> （第三层是回写状态幂等，第 4 段会看到。）

**操作 3**：点 **「上传合同」**，选 `samples/01_软件采购合同_风险用例.docx`。

> 「经办人也可以直接上传。上传后自动进入审查队列 ——
> 看右侧的 **「审查队列与配额」** 面板，并发度是服务端钉死的，
> 四道配额分别是单文件大小、队列长度、待处理堆积、附件存储总量。
> 有人刷单不会把系统堵死。」

**操作 4**：在列表里打开刚上传的合同 → 点 **「导出 Markdown」**。

> 「经办人能看风险点、能下载报告，但注意看他**没有**什么：
> 没有回写按钮、没有改规则的入口。这就是 2.4.2 的边界。」

**操作 5**（可选，展示自动流转）：回大盘，打开 **「自动流转 · 定时拉取」** 开关。

> 「这是 v2.0 新增的自动化：系统自己按间隔去拉待办并审查，不用人点。
> 连续失败会按倍数退避并封顶，成功一次就复位。**默认是关闭的** ——
> 否则演示数据会在没人操作的时候自己变。」

演示完**记得关掉**，让现场数据可控。

---

## 第 2 段 · 法务审查人：核对、改条款、回写（4 分钟）

**身份**：切到法务审查人（顶栏身份切换，或登录页一键进入）

**操作 1**：打开《核心业务系统软件采购合同》 → **「审查」** 进工作台。

**讲解（左栏）**：

> 「左边是合同正文，按页分页，每段前标了段落序号和识别出的条款类型，
> 橙色和红色是命中风险的原文，颜色对应风险等级。」

**操作 2**：在右栏点第一条 **PU-H-001 知识产权整体归属供应商**。

> 「点卡片，左边自动跳到对应页、对应段落并高亮 —— **卡片到原文**；
> 反过来点正文高亮，右边卡片被选中 —— **原文到卡片**。这就是双向锚定。
> 锚点是精确到字符区间的：解析时就记了页码、段落索引和起止字符位置，
> 所以能圈出那一句，而不是把整个条款糊成一片。」

**操作 3**：展开卡片里的 **「备选方案」** → 点 **「用此方案替换」** → 点 **「采纳建议」**。

> 「每一条风险都带**可直接落地的示范条款**，不是『建议注意知识产权』这种废话。
> 采纳之后写进库，右侧的『建议采纳进度』会跟着走。」

**操作 4**：看右侧 **「审查表达模式对照」** 面板。

> 「这里并排两块：左边是**规则引擎模式**，右边是**规则 + 模型润色模式**。
> 注意风险结论、等级、命中项两块是完全一致的 —— 因为**风险判定 100% 由确定性规则引擎产出，
> 大模型只改写措辞、不参与判定**。法务场景的结论必须能被质疑、追溯、复核，
> 模型自由判断满足不了这个要求。」
>
> 「当前线上没配 Key，所以右边显示『未启用』并**明示了原因**，
> 而不是假装有或者静默降级 —— 演示效果在任何环境下都是稳定的。」

**操作 5**：在「法务人工批注」写一句，比如
「第二、四条须按下述示范条款修改后方可用印；第六条补充保密期限。」→ 点 **「保存批注」**。

**操作 6**：点 **「写回审批单」** → 弹出结果 → 点 **「查看审批评论区」**。

> 「审查意见和法务批注一起写进审批单评论区了。请注意两件事：
> 一是系统**只会写评论，没有通过 / 拒绝 / 转交 / 撤回的能力**，
> 意见文本里固定带边界声明，审批权始终在人手上；
> 二是重复点写回会被幂等跳过 —— 第三层幂等。」

**操作 7**：点 **「导出 PDF」**。

> 「报告导出有三条通道：本机有浏览器时走无头打印（排版最佳）；
> **没有浏览器的服务器上走纯标准库直出** —— 按字节拼 PDF，
> 中文用 PDF 标准的非嵌入 CID 字体，还写了 ToUnicode 保证复制出来是汉字。
> 所以服务端 PDF 直出这件事在 Linux 实例上也是成的，不是靠本机浏览器撑着。」

## 第 3 段 · 系统管理员：规则、阻塞、可观测（3 分钟）

**身份**：切到系统管理员（`admin`）

**操作 1**：顶栏 **「合规规则与模板」**（法务和经办人的顶栏里**看不到这个入口**）。

> 「同一套规则库，按合同类型分开维护：采购、销售、服务、劳动四类共 41 条。
> 每条规则都有风险等级、条款类型、匹配模式、触发条件和法律依据。
> 规则在页面上可在线编辑并写回配置文件，**自动留 `.bak` 备份**。」

**操作 2**：打开一条规则的编辑框，指出 **「匹配模式」** 下拉：

> 「五种模式：关键词、正则、**必备条款缺失**（absence，全文范围判断，避免条款标题误报）、
> **权责不对称配对**（pair，我方不利条款与对方封顶条款同时命中才算）、数值阈值。
> 写坏的正则不会静默失效 —— 会被跳过并写进诊断，在工作台上能看到。」

**操作 3**：回大盘，筛选 **「解析受阻」**，打开那份加密 PDF 的任务 → 点 **「重新审查」**。

> 「文档加密、扫描件严重模糊、正文为空这三种情况，任务会进入 `blocked` 并**记录原因**，
> 而不是硬着头皮出个假结果。管理员修正文件或调整参数后一键重试。
> 另外 v2.0 补了**页眉页脚剔除**：跨页重复的页码、密级这些短行会被剔掉，
> 但条款标题和含甲方乙方金额的行在保护名单里，**永不被剔**。
> 剔了哪些行逐条写审计，剔完还会重算段落坐标，锚点照样能精确定位。」

**操作 4**：点 **「运行指标」** 与 **「机器人通知」**。

> 「可观测这块：请求量、错误率、慢请求、热点接口；审计日志覆盖拉取 → 下载 → 指纹 →
> 解析 → 元数据 → 切条款 → 规则命中 → 摘要 → 回写全过程，一键导出全量 JSON。」

讲通知时**必须**点出 v2.0 的变化：

> 「通知这里是 v2.0 的一个安全收口。之前通知正文会把合同相对方名称、金额、
> 统一社会信用代码原样发到钉钉群 —— 合同是最敏感的数据，而通知是**这个系统唯一把数据
> 送出本机的出口**。现在做了两层脱敏：字段级按规则掩码，外加一层整段正则兜底扫描
> （信用代码 / 金额 / 手机号 / 邮箱），并且**通知正文不允许携带合同正文片段**。
> 另外 `batch_summary` 和 `review_completed` 这两类默认关掉了，收敛外发面。」

**操作 5**：点 **「一键自检」**。

> 「52 项验收自检，全是真去解析文件、真跑规则引擎、真调回写接口、真做锚点一致性核对，
> 不是检查配置文件在不在。还有一条专门断言**版本口径一致** ——
> 交付版本 = 运行版本 = 文档版本，`/api/health` 必须返回真实版本号。」

## 第 4 段 · 越权反例（1 分钟，**别省**）

**身份**：切回法务审查人

**操作**：直接在地址栏输入 `/rules`。

**结果**：出现 403 权限受限页。

**讲解**：

> 「法务看不到规则页 —— 但重点不是页面藏没藏，而是**服务端真的拦住了**。
> 这个页面会说清楚三件事：你是谁、你缺哪个权限、这个权限归谁。
> 同时这次访问已经写进审计了，管理员在大盘的审计日志里能按 `auth.guard` 查到。
> 手工构造一个 `POST /api/rules/purchase` 也是一样的结果 ——
> 前端只是体验，**边界在服务端**。」

## 第 5 段 · 收尾（1 分钟）

> 「补充三点。」
>
> 「第一，**整条链路零第三方依赖**。解析 DOCX 用标准库 `zipfile` + `xml.etree`；
> PDF 是自研的对象扫描 + `/Filter` 链 + ToUnicode CMap；扫描件走系统自带 OCR；
> 连 PDF 报告都能纯标准库吐出来。装好 Python 就能跑，不需要联网装包。」
>
> 「第二，**这版是 v2.0**。相对上一版补齐了需求 2.4.2 的角色权限，
> 需求条目从 8/10 到 **10/10**；新增自动流转、页眉页脚剔除、模式对照、
> 服务端 PDF 直出、审查队列与配额；自检从 33 项到 **52 项**，HTTP 冒烟从 45 项到 **79 项**。
> 版本变更记录在 `CHANGELOG.md`。」
>
> 「第三，**不做的事也明确**：不引入任何第三方运行期依赖、不做真实审批联调、
> 不做多租户和 SSO。真实对接、容器化、能力压测这些在技术方案的附录里列成了
> 生产化升级路径，共 12 条，不在本项目范围内。」

## 演示时的坑（提前知道）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 打开页面直接跳登录页 | v2.0 起未登录一律跳转 | 正常，正是要演示的点；先登录再讲 |
| 「审查表达模式对照」右边显示未启用 | 线上/本机没配 LLM Key | 正常，页面会**明示原因**，按脚本里的话术讲 |
| 导出 PDF 弹出打印预览而不是下载 | 本机没找到 Edge / Chrome，降级到可打印 HTML | 打印对话框里「另存为 PDF」；有浏览器的机器上直接下载 |
| 一份加密 PDF 一直处理不了 | 刻意的受阻用例（`08_保密协议_加密用例.pdf`，口令 `contract2026`） | 正常，正好演示 `blocked` 与重试 |
| 自动流转的开关忘了关 | 演示数据会自己变 | 演示完回大盘关掉 |
| 身份切换后页面没变 | 顶栏切换会整页刷新 | 若没刷新，手动刷新一次 |
| 扫描件审查耗时明显长 | OCR 是链路里最重的一步（本机实测 0.6~0.8 秒） | 提前说明，别现场以为是卡了 |
