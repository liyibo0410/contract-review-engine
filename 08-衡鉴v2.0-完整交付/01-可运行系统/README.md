# 衡鉴 · 企业合同智能审查系统

> **衡**之对等公允，**鉴**之明察留痕。
> 读合同、找风险、写意见 —— 让审批人只做一件事：做决定。

面向企业合同审批场景的智能审查系统。支持 DOCX / PDF / 扫描件三类文档解析，
通过**确定性规则引擎 + 大模型语义增强**双引擎识别法律与商业风险，
提供原文高亮定位、修改建议生成、审批意见回写与审查报告导出。

---

## 一句话讲清技术定位

这不是"把合同丢给大模型然后让它写结论"。系统的核心主张是：

| 谁在做决定 | 做什么 | 为什么 |
| --- | --- | --- |
| **规则引擎（主路径）** | 判定风险等级、给出命中项与原文坐标 | 同一份合同任何时候跑都必须得到同一份结论；可复现才能被法务采信 |
| **大模型（增强路径）** | 解释成因、润色示范条款、检测跨条款矛盾 | 这些恰恰是规则写不出来、而模型擅长的部分；且失败可降级为模板 |

Prompt 中明确禁止模型新增或修改风险项，模型输出必须通过 JSON Schema 校验，
失败即降级 —— **演示零事故**不是靠祈祷，是靠每一条外部依赖都有兜底。

## 快速开始

### 方式一：一键启动（推荐）

```bat
双击 start.bat
```

脚本会依次完成：创建虚拟环境 → 同步依赖 → 生成样例合同集 → 启动服务 → 打开浏览器。

### 方式二：手动启动

```bash
# 1. 安装依赖（uv 管理，也可用 pip）
uv venv --python 3.11 .venv
uv pip install --python .venv/Scripts/python.exe -e .
# 扫描件 OCR 支持（可选，但验收项要求扫描件解析）
uv pip install --python .venv/Scripts/python.exe rapidocr-onnxruntime

# 2. 生成 13 份样例合同与黄金标注
cd backend && python tools/gen_samples.py && cd ..

# 3. 启动服务
uv run uvicorn app.main:app --reload --port 8130   # 在 backend 目录下执行
```

访问 <http://127.0.0.1:8130/>，接口文档 <http://127.0.0.1:8130/api/docs>。

### 配置大模型（可选）

复制 `.env.example` 为 `.env`，填入 `HJ_LLM_API_KEY`。
**不配置也能完整跑通全流程** —— 语义层会自动降级为确定性模板生成器，
审查意见、修改建议、回写内容一样不少，只是解释文字由模板拼装而非模型撰写。

## 核心能力与验收对照

| 验收标准 | 实现 |
| --- | --- |
| 接入并解析 DOCX / PDF / 扫描件 | 三引擎统一输出「段落树 + 页码 + 字符区间」 |
| 提取核心元数据与条款，记录页码位置 | 元数据 14 项 + 11 类条款，全部带坐标，可点击跳转原文 |
| 识别缺失条款、权责不对等、高危表述 | 31 条规则（高 11 / 中 13 / 低 8）+ 6 种判定类型 |
| 原文与风险卡片双向高亮定位 | 字符区间求交映射，点卡片跳页高亮，划原文反查风险 |
| 生成修改示范条款并支持法务编辑 | 13 套标准示范条款库，可编辑后采纳，生成修改前后对照 |
| 生成格式化审查意见并写回评论区 | Markdown 意见书 + 回写模拟器（DRY_RUN / 真实双模式，幂等三键） |
| 解析失败进入阻塞并支持重试 | 五种阻塞代码 + 可读原因 + 一键重试（清空重建，幂等键保留） |
| 端到端全流程演示 | 内置一键演示脚本，覆盖拉取→解析→审查→复核→回写→导出 |

## 安全边界（不可突破）

1. **只写意见，不改结论** —— 系统不提供任何通过 / 拒绝 / 转交 / 撤回能力；
2. **幂等三键** —— 合同编号 + 附件 SHA256 + 规则版本号，重复触发自动跳过；
3. **DRY_RUN 前置** —— 回写前先生成待写入正文，预览模式只落库不外发；
4. **全程留痕** —— 每个链路步骤写入 `audit_logs`，可从审查意见反查完整处理链路。

## 常见问题

**Q：启动后页面空白？**
A：确认服务根路径返回的是 `frontend/index.html`。若前端目录缺失，访问 `/api/docs` 可验证后端是否正常。

**Q：上传扫描件后任务变成"解析受阻"？**
A：这是设计行为。检查 `GET /api/system/health` 中 `ocr.available`，若为 `false` 则需安装 `rapidocr-onnxruntime`。
阻塞原因会明确区分"引擎缺失"与"图片模糊"，两者的处理方式不同。

**Q：报告导出 PDF 是乱码？**
A：PDF 使用 PyMuPDF 内置中文字体 `china-s`，无需额外字体文件。若仍异常，请先导出 Markdown 版本。

**Q：大模型接口超时会不会导致审查失败？**
A：不会。超时（默认 8 秒）或返回非法 JSON 时自动降级为模板生成器，审查链路与输出结构完全不变。
