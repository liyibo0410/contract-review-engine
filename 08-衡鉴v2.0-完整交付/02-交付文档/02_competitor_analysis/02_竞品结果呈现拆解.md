# 竞品结果呈现拆解

**一句话结论**：结果呈现决定"法务是否采信"——分级让人一眼看轻重、原文定位让人立刻核对、解释性数据让人相信判据；衡鉴用"字符区间双锚定 + 风险卡片 + 合同画像雷达图 + 审计时间轴"四件套，把可采信建立在可复现证据上。

> 竞品具体 UI 均**基于公开资料的推断**，以「推断」标注；本项目功能以基线为准。

---

## 1. 风险项分级展示

| 竞品流派 | 分级方式（推断） | 评价 |
| --- | --- | --- |
| 电子签平台 | 高/中/低或"建议修改/提示" | 粒度粗，常混入"提示性"噪声 |
| 幂律类 | 高/中/低 + 条款维度聚合 | 接近专业审查，但分级口径未公开 |
| iCourt 类 | 人工标记为主，工具辅助高亮 | 分级由人定，一致性靠人 |
| 通用大模型 | 多无分级，或模型自定"严重/一般" | 不稳定，同一合同多次结果不同 |
| **衡鉴** | 32 条规则明确 `high/medium/low`（高 11/中 13/低 8），`findings` 按等级排序 | 分级来自规则等级， deterministic |

**为什么本项目这么做**：分级不是模型"感觉"，而是规则写死的风险等级，同一合同永远同分级——这是可复现的前提，也是法务建立信任的基础。

---

## 2. 原文如何定位

| 流派 | 定位方式（推断/事实） | 局限 |
| --- | --- | --- |
| 电子签/幂律 | 条款高亮、段落引用 | 多在"段落/句子"粒度，跨格式不一致 |
| 通用大模型 | 复制原文片段或"第几段" | 无精确坐标，复核要人肉翻找 |
| **衡鉴** | 统一坐标系 `[char_start, char_end)` + `page`/`para_index` 人话定位 | 三格式同构，前端一种高亮逻辑 |

**双锚定取舍**：`char_start/char_end` 是机器真理坐标（回写、复核都用它），`page/para_index` 只给人看。多数方案止步于"给风险段落文字"，而**从风险到字符级定位的完整证据链**才是法务敢采信的前提（基线第三章）。`GET /{id}/document` 提供带锚点的段落序列，`GET /{id}/findings` 给卡片列表。

---

## 3. 中间解释性数据（为什么判为风险）

这是"让人相信"的关键层。拆解三类做法：

| 流派 | 解释性数据（推断） | 问题 |
| --- | --- | --- |
| 电子签/幂律 | 风险原因文字 + 条款引用 | 多不暴露"命中了哪条规则/哪个词" |
| 通用大模型 | 自由文本解释 | 幻觉风险，无法反查依据 |
| **衡鉴** | 每条 finding 含 `evidence_text`(命中原文) + `reason`(为何判) + `legal_basis`(法条) + `advice`(修改建议) + `rule_id` + `rule_version` | 暴露完整判据，可溯源 |

**为什么本项目这么做**：解释性数据不是"锦上添花"，而是合规责任链的一部分。法务要能回答"系统凭什么这么说"——`legal_basis` 给法条出处、`rule_id` 给可复现判据、`evidence_text` 给原文锚点，三者缺一不可。

---

## 4. 本项目的四件套呈现与取舍理由

### 4.1 字符区间双锚定（已述，见第 2 节）
统一 `full_text` 坐标系，机器坐标 + 人话坐标并存。

### 4.2 风险卡片
`GET /{id}/findings` 返回按等级排序的卡片列表，每张卡含：等级、条款类型、命中原文、原因、法条、建议、坐标。前端 `workbench.html` 双栏联动（左原文高亮、右卡片）。

**取舍理由**：卡片比"长报告"更适合审查人逐条处理；双栏联动让"点卡片→跳原文"和"点原文→看卡片"双向可达，减少认知切换。

### 4.3 合同画像雷达图
`writer.py` 做"合同画像六维评分"，`profile_json` 落 `contracts` 表。前端以雷达图呈现合同在各维度的风险分布。

**取舍理由**：单份合同的风险清单是"点"，画像雷达是"面"——让审查人一眼看出"这份合同烂在知识产权还是付款"，而不是陷在 11 条明细里。**注意**：六维的具体维度定义未在基线中展开（**【未开发/未文档化】维度口径**），对外表述需谨慎。

### 4.4 审计时间轴
`audit.py` 以 Step 上下文管理器写 `audit_logs`，前端 `eval.html` / 审计接口呈现时间轴：`step` / `tool` / `input_digest` / `output_digest` / `cost_ms`。

**取舍理由**：时间轴把"系统做了什么"变成可回放的证据，配合 `hitl_actions` 的"人做了什么"，构成"机器执行 + 人决策"双轴留痕。这是责任归属闭环的可视化层（基线第九章）。

---

## 5. 呈现层的差异化小结

| 能力 | 多数竞品（推断） | 衡鉴 |
| --- | --- | --- |
| 分级来源 | 模型/人工 | 规则等级（确定性） |
| 定位精度 | 段落级 | 字符级双锚定 |
| 解释深度 | 原因文字 | 原文+原因+法条+建议+规则ID |
| 整体视图 | 列表/报告 | 雷达图 + 时间轴 |
| 可复现 | 弱 | 强（规则版本 + 坐标） |
