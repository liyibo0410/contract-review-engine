# 竞品审核流程拆解

**一句话结论**：主流合同审查产品的流程都可抽象为"上传 → 解析 → Agent 审核 → 人工审核 → 结果回写"五段，差异主要在**解析深度、判定是否确定性可复现、回写是否越权**；衡鉴的差异化在于"规则引擎做唯一判定 + 字符级证据链 + 只写评论不写结论"。

> 说明：除"通用大模型直接审合同"为可复现的公开行为外，其余商业产品的具体功能均**基于公开资料的推断**，无法逐条核实，文中以「推断」标注不确定性。本项目功能以 `docs/00_setup/项目事实基线.md` 为准。

---

## 1. 竞品选取理由

| 竞品 | 选取理由 | 对标维度 |
| --- | --- | --- |
| 腾讯电子签 / 法大大 / e签宝 合同审查模块 | 电子签约平台自带审查，离"审批回写"场景最近 | 流程完整性、回写集成度 |
| 幂律智能（MeCheck 等） | 专注 AI 合同审查的法律科技公司，规则/模型双路径代表 | 规则体系、垂直深度 |
| iCourt 类法律科技产品 | 面向律师/法务的培训+工具生态，代表"人工主导+辅助"流派 | 人工介入点设计 |
| 通用大模型（GPT/DeepSeek）朴素做法 | 零集成、零流程，直接贴文本让模型审，是"无产品"的基线对照 | 自动化上限与下限 |

---

## 2. 流程拆解（五段通用模型）

```
上传合同 ──► 解析处理 ──► Agent 审核 ──► 人工审核 ──► 结果回写
（格式/权限）  （OCR/结构化） （风险标注）   （确认/改）   （系统/评论区）
```

### 2.1 上传
- 平台型（电子签）：在签约流程内嵌，合同天然数字态，少格式问题。
- 法律科技型：多支持 DOCX/PDF 上传，扫描件依赖 OCR。
- 通用大模型：用户手动粘贴文本或上传，无格式治理。
- **本项目**：`POST /api/contracts/upload`（multipart，`auto_run` 控制后台跑），另支持 `POST /api/contracts/pull` 从审批系统拉待办（内置模拟器）。

### 2.2 解析处理
- 平台型/法律科技型（推断）：多引擎解析 + 段落/条款识别，具体坐标系是否统一未知。
- 通用大模型：基本不解析，直接吃整段文本，长合同易截断、定位靠模型"大概"。
- **本项目**：DOCX（python-docx，识别分页符）/ PDF（PyMuPDF 页+块）/ 扫描件（RapidOCR 行框还原阅读顺序）三引擎**统一到 `full_text` 坐标系**，定位精度到字符区间（基线第三章）。

### 2.3 Agent 审核
- 法律科技型（推断）：规则 + 模型混合，强调可配置规则库与行业模板。
- 平台型（推断）：以模板/标准条款比对为主，垂直深度有限。
- 通用大模型：单次 prompt 输出风险列表，**不可复现、无证据链、易幻觉**。
- **本项目**：确定性规则引擎（32 条、8 种判定）为**唯一判定来源**，LLM 仅做解释/建议/跨条款矛盾检测，判定可复现可审计（基线第四章、`rule_engine.py`）。

### 2.4 人工审核
- 几乎所有产品：人工确认/修改风险、补充意见。
- iCourt 流派（推断）：人工主导，工具只做检索/比对，AI 不替人定性。
- **本项目**：四动作 `approve/edit/reject/resume`，与 LangGraph `interrupt` 对齐，`hitl_actions` 落动作流水（基线 6.3）。

### 2.5 结果回写
- 平台型（推断）：回写签约/审批系统，能力强但可能直接落"结论"。
- 通用大模型：无回写，靠人复制粘贴。
- **本项目**：`POST /api/contracts/{id}/writeback`，**只写审批评论区**，DRY_RUN 预览 + 幂等三键 + 无审批结论接口（基线第九章）。

## 3. 逐竞品对比表

| 维度 | 电子签平台 | 幂律类 | iCourt 类 | 通用大模型 | 衡鉴 2.0 |
| --- | --- | --- | --- | --- | --- |
| 上传集成 | 强（内嵌） | 中 | 弱 | 无 | 中（pull 模拟器） |
| 解析坐标系 | 推断：未知 | 推断：条款级 | 推断：段落级 | 无 | 字符级统一 |
| 判定可复现 | 推断：部分 | 推断：规则可配 | 推断：人工为主 | 否 | 是（规则唯一） |
| 人工介入点 | 推断：确认 | 推断：确认/改 | 主导 | 全人工 | 四 HITL 动作 |
| 回写越权风险 | 推断：可能落结论 | 推断：视产品 | 低 | 无 | 红线：只写评论 |
| 证据链溯源 | 推断：弱 | 推断：中 | 推断：靠人 | 无 | 强（char 区间+audit） |

> 上表"推断"列均为基于公开资料的推断，具体以各产品官方文档为准；衡鉴列以基线为准。

## 4. 与本项目的关键差异小结

1. **判定来源**：多数产品把模型输出当风险，衡鉴把规则引擎当唯一判定，模型只增强——决定可复现性。
2. **定位精度**：统一字符坐标系是多数产品未公开宣称的能力，也是法务采信的前提。
3. **回写边界**：本项目用工程红线硬隔离"出意见"与"下结论"，多数平台型产品可能直接碰审批结论。
4. **流程中断语义**：`interrupt` 式 HITL 把"人等机器"转成"机器等人做决定"，与 LangGraph 对齐。
