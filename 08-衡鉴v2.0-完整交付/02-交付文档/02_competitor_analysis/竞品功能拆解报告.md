# 衡鉴 2.0 竞品功能拆解报告

> 正式交付物 ｜ 面向对象：评委 / 客户
> 编制：市场团队 ｜ 基线版本：2.0.0 ｜ 日期：2026-09-19

**一句话结论**：在"合同 AI 审查"赛道，多数产品强在流程集成、弱在判定可复现与责任可溯源；衡鉴以"确定性规则引擎为唯一判定 + 字符级证据链 + 只出意见不下结论"形成差异化，护城河是统一坐标系与回写红线，边界是明确"不碰审批结论"。

## 2. 流程拆解（五段通用模型）

```
上传 ──► 解析 ──► Agent 审核 ──► 人工审核 ──► 回写
```

| 阶段 | 平台型（推断） | 法律科技型（推断） | 通用大模型（事实） | 衡鉴 2.0（基线） |
| --- | --- | --- | --- | --- |
| 上传 | 内嵌，数字态 | DOCX/PDF 上传 | 手动粘贴/上传 | `POST /upload`（`auto_run`）+ `POST /pull` |
| 解析 | 多引擎，坐标系未知 | 多引擎+条款识别 | 基本不解析 | DOCX/PDF/扫描件三引擎统一坐标系 |
| Agent 审核 | 模板比对为主 | 规则+模型混合 | 单次 prompt，不可复现 | 规则引擎唯一判定，LLM 仅增强 |
| 人工审核 | 确认/修改 | 确认/修改 | 全人工 | `approve/edit/reject/resume` |
| 回写 | 可能落结论 | 视产品 | 无（复制粘贴） | 只写评论区，DRY_RUN+幂等三键 |

## 4. 三处关键差距分析

### 差距一：判定可复现性（最关键的差距）

- **竞品现状（推断）**：多数把模型输出直接当风险，同一合同多次审查结果可能不同，无法作为可审计依据。
- **衡鉴做法**：规则引擎（32 条、8 种判定）是**唯一判定来源**，LLM 只做解释/建议/跨条款矛盾检测；同合同同规则版本必得同清单。
- **为什么是差距**：审查意见一旦要进入企业审批与潜在诉讼，**可复现 = 可追责**，模型随机性是法务无法接受的。
- **诚实残留**：规则靠固定词表，同义改写可能漏判（假阴性）；内部 100% 召回 ≠ 泛化（盲测集未开发）。

### 差距二：定位精度与证据链完整性

- **竞品现状（推断）**：定位多停在"段落/句子"，跨格式（DOCX/PDF/扫描件）不一致，复核要人肉翻找。
- **衡鉴做法**：统一 `full_text` 坐标系，三格式同构映射到字符区间；每条 finding 带完整证据链。
- **为什么是差距**：法务采信前提是"原话在哪、为什么判"，字符级定位 + 证据链把"可信"落到工程上。
- **诚实残留**：PDF 跨页断句、OCR 阅读顺序错乱时坐标可能漂移（**【未开发】人工校正切分**）。

### 差距三：回写的责任边界

- **竞品现状（推断）**：平台型产品回写能力强，但可能直接落"通过/拒绝"等审批结论，责任归属模糊。
- **衡鉴做法**：工程红线——只写评论区、无审批结论接口、DRY_RUN 前置、幂等三键、状态机兜底。
- **为什么是差距**：AI 出具意见存在合规风险，把"出意见"与"下结论"硬隔离，是法律责任边界也是产品护城河。
- **诚实残留**：系统标注"仅供参考"与法律上责任切割并非同一件事，仍需法务在流程上确认。

## 5. 本项目的差异化定位与护城河

### 5.1 差异化定位

> **企业合同审批前的"数字法务初筛 + 可溯源意见回写"**，不做终审、不做签约、不碰审批结论。

- 与平台型差异：不取代签约/审批系统，只做其前的审查增强；
- 与法律科技型差异：判定确定性、证据链完整度更高；
- 与通用大模型差异：可复现、可审计、有工程红线。

### 5.2 护城河（三层）

| 层级 | 护城河 | 难以复制原因 |
| --- | --- | --- |
| 数据/规则 | 32 条规则 + 14 套示范条款 + 黄金标注同源生成 | 与样例合同同源，标注零错位 |
| 工程 | 统一字符坐标系 + 回写红线 + 审计闭环 | 需全链路重构，非 prompt 可补 |
| 流程 | 四 HITL 动作 + 动作流水 | 把"人做终裁"固化进状态机 |

### 5.3 我们不做什么（边界声明）

1. **不提供**通过/拒绝/转交/撤回等任何改变审批结论的动作（基线第一章）；
2. **不做**无证据链的"AI 直接下法律结论"（显失公平、无效等定性由人定）；
3. **不采用**脱离规则引擎的纯模型判定主路径（LLM 仅增强）；
4. **不宣称** 100% 泛化能力（内部回归基线 ≠ 第三方盲测，盲测集未开发）；
5. **不越权回写**（只写审批评论区，无审批结论写接口）。

## 6. 对客户/评委的收口话术

- "衡鉴不是要代替法务，而是让法务把 30–60 分钟的通读压缩成'看风险卡片'。"
- "我们的判定是确定的、可复现的、带字符级证据链的——您今天看和明天看，结论一样。"
- "我们明确不替您做通过/拒绝，AI 的意见只写在评论区，最终签字的人还是您。"
