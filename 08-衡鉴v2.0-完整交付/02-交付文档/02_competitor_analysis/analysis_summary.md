# 竞品分析收口汇总（Lead 视角）

**一句话结论**：竞品的共同短板是"判定不可复现、定位不够精确、回写可能越权"；衡鉴的差异化定位是"规则引擎做唯一确定性判定 + 字符级证据链 + 只出意见不下结论"，护城河在坐标系与回写红线，但须诚实承认通用大模型在"零集成灵活度"上的优势不可硬碰。

---

## 一、流程维度共识

1. 行业通流均为"上传→解析→Agent 审核→人工审核→回写"五段。
2. 解析深度与回写集成度是平台型产品的强项（内嵌签约流），但**回写越权风险**也随之升高。
3. 人工介入点普遍设在"确认/修改"，但鲜少有与 `interrupt` 对齐的显式动作流水。

## 二、呈现维度共识

1. 分级展示普遍有，但分级**来源**多为模型/人工，确定性与衡鉴的规则等级不同。
2. 原文定位多数停在段落级，字符级双锚定是衡鉴的可采信壁垒。
3. 解释性数据多数只给"原因文字"，衡鉴给"原文+原因+法条+建议+规则ID"完整判据。

## 三、差异化策略结论

| 策略点 | 结论 | 支撑 |
| --- | --- | --- |
| 唯一判定来源 | 规则引擎做判定，LLM 只增强 | 可复现、可审计 |
| 坐标系壁垒 | 统一 `full_text` 字符坐标系 | 三格式同构、前端一种高亮 |
| 回写红线 | 只写评论区、无审批结论接口 | 合规责任边界 |
| 证据链呈现 | 风险卡片 + 雷达图 + 审计时间轴 | 让人采信 |

## 四、护城河与边界声明（预演正式报告）

- **护城河**：确定性判定 + 字符级证据链 + 回写红线，三者组合难以被"套个 prompt"的朴素方案复制。
- **边界（我们不做什么）**：
  1. 不提供通过/拒绝/转交/撤回等任何改变审批结论的动作（基线第一章）；
  2. 不做无证据链的"AI 直接下法律结论"；
  3. 不做脱离规则引擎的纯模型判定主路径；
  4. 不宣称 100% 泛化能力（内部回归 ≠ 盲测，盲测集未开发）。

## 五、对后续阶段的输入

- 对外材料统一口径：判定可复现、定位字符级、回写只评论；
- 凡涉竞品具体功能，一律标注"基于公开资料推断"，禁止写成已核实事实；
- 雷达图六维口径需先补全文档再对外（**【未文档化】**）。
