# 衡鉴 2.0 · 前端交互设计规范（正式交付物）

> **一句话结论**：前端是零构建、零 CDN 的原生 HTML/CSS/JS 深色工作台，4 个页面共用一套设计系统；核心交互是"左原文 / 右风险"双栏以**字符区间求交**联动高亮，所有动效只用于表达状态变化。以下描述均与 `frontend/` 下 4 个 HTML + 5 个 JS 的实现逐一核对。

| 页面 | 路由 | 角色 | 核心区块 |

## 三、核心交互详解

### 3.1 双栏联动的字符区间求交逻辑（关键）

统一坐标系 `full_text` 是一切高亮的基础。左栏每个段落带 `data-start/data-end`，右栏每个风险项带 `char_start/char_end`，二者靠**区间求交**建立映射（`workbench.js`）：

```js
function overlap(a1, a2, b1, b2) { return a1 < b2 && b1 < a2; }
// a1=段落起点 a2=段落终点；b1=风险起点 b2=风险终点
```

`applyHighlights()` 对左栏每个 `<p>`：遍历所有 findings，若存在 `overlap`，取**最高严重度**（rank: high=0/medium=1/low=2）作为该段高亮色，加 `hl-high/hl-medium/hl-low` 类。
**为什么这样做**：DOCX/PDF/扫描件三种来源都重建成同一套字符区间，前端只需一套高亮逻辑，无需为每种格式单独处理——这是统一坐标系壁垒在前端的落地。

### 3.2 点卡片跳页高亮

`focusFinding(f)`：点右栏 `fcard` → 左栏找到与之 `overlap` 的段落 → `scrollIntoView({block:'center'})` → 延迟加 `pulse` 类（蓝底脉冲动画）→ 同步给卡片加 `active` 类并滚动到可视区。

### 3.3 划选原文反查风险

`document.mouseup` 监听：选中文本 ≥4 字 → 定位所属段落 → 由选中文本在段内的偏移算出字符区间 `[cs, ce)` → `filter` 出与之 `overlap` 的 findings → 弹 `modal('片段研判')` 列出涉及风险项；若无命中则提示"该片段未命中规则；如需针对性意见，请由法务人工补充批注"。同时反查条款类型（`clauseRanges`）并展示。

### 3.4 采纳建议（可编辑）

`adopt(fid)`：点"采纳建议"→ 弹窗展示原条款位置、证据文本、可编辑的建议 `textarea` → 提交 `POST /findings/{fid}/adopt {adopted:true, adopted_text}`。采纳后卡片显示"已采纳"标签、记录 `adopted_text`，并计入审查意见书。已采纳可"撤销采纳"（`adopted:false`）。另有"复制条款"按钮复制建议文本到剪贴板。

### 3.5 键盘流

| 键 | 行为 | 前提 |
| --- | --- | --- |
| `j` / `k` | 下/上切换风险项并跳页高亮 | 非输入态、有 findings |
| `Enter` | 采纳当前激活风险项（`adopt`） | 有 `W.active` 且非输入态 |
| `/` | 聚焦自然语言检索框 `nlq` | 非输入态 |
| `Esc`（输入框内） | 失焦 | 输入态 |

输入框（INPUT/TEXTAREA/SELECT）内不触发 `j/k/Enter`，避免与输入冲突。

### 3.6 自然语言检索（彩蛋）

`nlq()`：`POST /search {query}` 把口语提问映射到条款类型（付款/验收/违约/保密/IP/数据/争议/效力/不可抗力/主体），返回 Top3 命中片段，点击可跳页高亮。

## 四、设计规范（取自 `app.css :root` 真实色值）

### 4.1 色彩变量（实测）

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#0B0E14` | 页面底色 |
| `--bg-1` | `#11161F` | 卡片/顶栏 |
| `--bg-2` | `#161C27` | 内层卡片/风险卡 |
| `--bg-3` | `#1D2533` | 按钮/悬浮 |
| `--line` | `#232C3B` | 边框主色 |
| `--line-2` | `#2E394B` | 次级边框/分隔 |
| `--text` | `#E6EAF2` | 主文字 |
| `--text-2` | `#A7B0C0` | 次级文字 |
| `--text-3` | `#6E7A8D` | 辅助/占位文字 |
| `--brand` | `#4C8DFF` | 品牌蓝/主操作 |
| `--brand-dim` | `#2C5FA8` | 激活态底/渐变起 |
| `--high` | `#FF5D5D` | 高风险/错误 |
| `--high-bg` | `rgba(255,93,93,.12)` | 高风险底色 |
| `--medium` | `#FFA93B` | 中风险/警告 |
| `--medium-bg` | `rgba(255,169,59,.12)` | 中风险底色 |
| `--low` | `#7C8798` | 低风险 |
| `--low-bg` | `rgba(124,135,152,.12)` | 低风险底色 |
| `--ok` | `#35CE8D` | 成功/通过 |
| `--ok-bg` | `rgba(53,206,141,.12)` | 成功底色 |
| `--warn` | `#F5C542` | 提示黄 |

> 风险三色 + 成功绿 + 品牌蓝构成完整语义；所有语义色都配套 `-bg` 半透明底，用于卡片左边框/段落高亮，保证深色底上的对比度。

### 4.2 字号阶梯

| 位置 | 字号 |
| --- | --- |
| 基础正文 | 14px / line-height 1.6 |
| 指标数值 `.stat .v` | 26px（等宽 mono） |
| 文档段落 `.doc p` | 14.2px / 行高 1.95 |
| 风险卡标题 `.fcard .t` | 13.5px |
| 卡片标题 `.card-title` | 13px |
| 标签 `.tag` | 11px |
| 辅助文字 `.small` | 12px |

### 4.3 间距与圆角

- 主区内边距 `main` 20px；卡片 `padding 16px`；网格间距 `gap 14px`（次级 10/8px）；`pane-body` 左 18×22px、右 12×14px。
- 圆角：`--radius: 10px`（卡片、下拉、模态）；`--radius-sm: 6px`（按钮、输入框、标签）；进度条/滚动条 5px。
- 阴影：`--shadow: 0 6px 24px rgba(0,0,0,.35)`（仅模态/悬浮卡片）。

### 4.4 动效原则（克制）

**动效只用于表达状态变化**，不使用装饰性动画：

| 动效 | 触发场景 | 含义 |
| --- | --- | --- |
| `pulse` | 跳页高亮 / 划选跳转 | 蓝底脉冲 2 次，提示"看这里" |
| `blink` | 时间轴当前节点 | 呼吸闪烁，表示"进行中" |
| `slidein` | toast 出现 | 从下方滑入 |
| `rot` | `.spin` 加载 | 旋转，表示后台进行 |
| `transition .16s` | 按钮/卡片 hover、边框聚焦 | 仅颜色/边框过渡 |

设计取向（CSS 注释原话）："信息密度优先于留白，对比度优先于柔和，动效只用于表达状态变化。"

## 五、状态与空态设计

| 状态 | 视觉 | 文案（代码实写） |
| --- | --- | --- |
| **Loading** | `.spin` 旋转 + "等待流水线事件…" + 顶部"流水线运行中"标签 | "正在上传…" / "正在解析合同文档" / SSE 实时进度条 |
| **空态（列表）** | `.empty` 居中灰字 | "暂无审查任务" |
| **空态（正文）** | `.empty` | "选择一份合同开始审查" / "暂无正文数据" |
| **无结果（审查）** | `.empty` | `completed` 且零命中："未命中任何风险项，合同条款齐备。"；非完成："尚未产生审查结果。" |
| **阻塞态** | 红色 `banner` + `blockedBox` + 重试按钮 | "任务已阻塞（需人工处理）"+ `block_reason` + 处理建议 + "重新解析/重试" |
| **错误态** | 红 toast / "服务未就绪" | 上传失败/回写失败/接口 400/409/413 均用可读中文 `detail` |

**健康灯**：顶部 `healthBox` 用绿点/红点表达规则在线、语义层在线/降级、OCR 就绪/不可用；服务不可达显示"服务未就绪"（红点）。

## 六、响应式断点与降级

| 断点 | 行为 |
| --- | --- |
| `>1180px` | 工作台双栏：`grid-template-columns: minmax(0,1fr) 440px`，左右并排 |
| `≤1180px` | **单栏堆叠**：`.wb` 改 `1fr`、`height:auto`，右栏落到左栏下方 |
| `≤1200px` | 指标网格 `.c4/.c6` 降为 2 列 |
| `≤900px` | `.c2/.c3` 降为 1 列 |

**为什么 1180px 是工作台分界**：双栏要求左文右卡各有舒适宽度，窄屏下并排会挤压阅读区，故直接堆叠而非强行双栏。其余网格按列数自适应降列，保持信息不丢。
