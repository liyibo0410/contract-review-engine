# 反方风险清单（站在反方立场审视技术难点）

**一句话结论**：这个场景最大的反方论据不是"做不做得到"，而是"凭什么信你"——误报会淹没真风险、AI 越权下结论会带来合规责任、跨条款语义判断仍必须留在人手里；衡鉴用视角解析 / 适用面 / 排除语境 / 共现判定四道闸门压误报，但"内部 100% 召回 ≠ 泛化能力"是必须诚实承认的残余风险。

> 本文所有机制描述均对照 `backend/app/services/rule_engine.py` 与 `backend/app/rules/rules_v1.yaml` 核实；量化数据仅引用基线第八章，未新增任何数字。

---

## 1. 误报（false positive）问题

### 1.1 反方论点：关键词匹配必然大面积误报

朴素做法（见 `02_竞品审核流程拆解.md` 的"通用大模型朴素做法"）是全文搜"无限责任""管辖"等词。反方会指出：

- "知识产权归甲方所有"——采购合同里对我方**有利**，销售合同里对我方**不利**；脱离视角必误报。
- "违约金累计不超过合同总价 20%"——是在讲**上限**，不是"违约金过高"。
- "对方承担无限责任"——对我方**有利**，但关键词匹配会当成风险。
- "质保期自验收合格后 12 个月"——质量条款里出现"验收"，会掩盖"付款根本没挂钩验收"的真问题。

基线第八章诚实声明：黄金标注与规则库由**同一团队同步编写**，因此 100% 召回是**内部回归基线**，不等于面对全新语料的泛化能力。

### 1.2 本项目的四道防误报闸门（已对照代码核实）

#### 闸门一：视角解析 `{我方}` / `{对方}`

`rule_engine.py:build_ctx` 按 `biz_type` 推断我方身份：采购/服务/劳动 → 我方=甲方；销售 → 我方=乙方。规则库用占位符书写（如 `知识产权归{对方}所有`），运行期 `_resolve` 实例化。

**为什么这么做**：让同一条规则在采购/销售两种合同里含义翻转，避免视角错配导致的系统性误报。

#### 闸门二：`biz_types` 规则级适用面

每条规则可声明 `biz_types`。例如：
- `HJ-H-002`（付款缺少验收前置）仅 `采购/服务` 生效，劳动合同不适用"付款挂钩验收"的语境；
- `HJ-H-011`（竞业限制无补偿）仅 `劳动` 生效。
`rule_engine.evaluate` 中 `if biz_types and biz not in biz_types: continue` 直接跳过。

**为什么这么做**：把"这条规则在哪种业务里才有意义"前置成硬过滤，而不是靠关键词去猜。

#### 闸门三：`exclude_keywords` 排除语境

| 规则 | 类型 | 排除语境 |
| --- | --- | --- |
| `HJ-H-006`（违约金>30%） | numeric | `不超过` `上限` `封顶` `以内` |
| `HJ-H-008`（我方无限责任） | regex | `以合同总价为限` `不超过` `上限为` `赔偿上限` `上限不超过` |
| `HJ-H-002`（付款无验收） | required_combo | `require_exclude`：`无需` `不予` `不支付` 等否定词 |

`rule_engine.py:_judge_numeric` / `_judge_regex` 均在命中后先检查排除词，命中即跳过。

**为什么这么做**：违约金上限表述与"违约金过高"表述在字符上高度相似，只能用"是否含上限限定词"来区分语境。

#### 闸门四：共现判定（required_combo）

`HJ-H-002` 要求**同一句话**里既出现付款语境（`付款/支付/价款/结算/货款/服务费`）又出现验收语境（`验收合格/验收通过/终验/考核合格…`）才认定"付款已挂钩验收"。若只在质量条款出现"验收"，付款条款本身无验收绑定，仍会命中。

**为什么这么做**（代码注释原文）：质保条款里一句"质保期为验收合格后 12 个月"会把付款环节根本没有验收前置的问题掩盖掉——共现而非"全文出现过"才是正确判据。

#### 补充闸门：缺失类规则的 `rescue_keywords` / `if_any` 前提

- `missing_clause`（如 `HJ-H-009` 缺失违约责任）带 `rescue_keywords`，若正文出现"违约金/违约方/赔偿责任"即视为该条款存在，不算缺失；
- `absent`（如 `HJ-M-002` 不可抗力无通知时效）带 `if_any` 前提：只有合同真的提了"不可抗力"，才去查"有没有通知要求"。

### 1.3 残余风险（诚实，不粉饰）

| 残余风险 | 说明 |
| --- | --- |
| 同义改写绕过关键词 | 规则靠固定词表，若对方用"我方须就一切后果负全责"而非"承担无限责任"，可能漏判（假阴性）。这是规则引擎的结构性上限。 |
| 视角推断只按 biz_type | `build_ctx` 默认"销售=我方乙方"，若合同实际角色错位（如我方作为甲方采购却标成销售），视角会整盘翻转。 |
| 共现窗口固定 | `required_combo` 要求"同一句"，若付款与验收分属相邻两句但语义确实解耦，仍可能误判或漏判。 |
| 100% 是内部回归值 | 基线已声明：同团队同步编写黄金集，泛化能力需第三方盲测集，已列入路线图但未做（**【未开发】盲测集**）。 |

## 2. 人工审核不可替代的边界

反方会问："既然能判风险，为什么不直接给通过/拒绝？"——因为以下判断**系统不能、也不应下结论**：

| 判断类型 | 为什么必须人做 | 系统角色 |
| --- | --- | --- |
| 商业是否可接受 | "预付款 60% 无担保"是风险，但战略供应商可特批 | 只标风险 + 给建议，不代决策 |
| 谈判空间评估 | 哪条能让步、哪条是底线，取决于商业关系 | 展示风险，供人权衡 |
| 法律结论定性 | "显失公平可撤销"需结合缔约背景，非纯文本能定 | 引用法条，不下"无效/可撤销"结论 |
| 证据链法庭采信 | AI 意见能否作为证据，由人/律师判断 | 提供可溯源依据，不承诺法律效力 |

基线第九章红线第一条：**后端不存在任何审批结论写操作接口**，只写评论区。这是产品边界，也是法律责任边界。

## 3. 责任归属：AI 出具意见的合规风险与控制措施

### 3.1 风险点

- **错判责任**：系统误判导致法务漏看真风险，谁担责？
- **过度信任**：用户把 AI 意见当终审，跳过人工复核。
- **不可溯源**：意见若无法反查到原文与规则，出事说不清。

### 3.2 本项目的控制措施（对照基线）

| 控制项 | 机制 | 出处 |
| --- | --- | --- |
| 证据链 | 每条 finding 带 `char_start/char_end`、`evidence_text`、`rule_id`、`reason`、`legal_basis` | findings 表定义 |
| 可溯源 | `audit_logs` 记录每步 `step/tool/input_digest/output_digest/cost_ms`，可从审查意见反查完整链路 | 基线第九章 |
| 只写意见不改结论 | 回写状态机只写评论区，无审批结论接口 | 基线第九章红线 1 |
| DRY_RUN 前置 | 回写前先预览正文，预览模式只落库不外发 | 红线 2 |
| 幂等三键 | `合同编号｜附件 SHA256｜规则版本号`，重复触发返回既有结果记 `writeback.skip` | 红线 3 |
| HITL 动作流水 | `approve/edit/reject` 谁做的、改了什么，天然留痕 | hitl_actions 表 |

### 3.3 残余风险

- **意见质量依赖规则库**：规则库本身有误（如法条引用过时），系统会"自信地错"。当前无外部法条实时校验（**【未开发】法条时效校验**）。
- **免责声明的实际效力**：系统标注"仅供参考"与法律上的责任切割并非同一件事，仍需法务在流程上确认。
- **LLM 降级风险**：`llm.py` 超时/非法即降级到纯规则，降级后解释质量下降，但判定不受影响（这是有意为之的设计取舍）。

## 4. 反方可能提出、但本项目已正面回应的其他难点

| 反方论点 | 本项目回应 | 残余 |
| --- | --- | --- |
| 扫描件识别不可靠 | 三引擎统一坐标系；OCR 低置信度（<0.35）进 `OCR_LOW_CONFIDENCE` 阻塞，区分"引擎缺失"与"图片模糊" | 极端模糊件仍可能错切分（**【未开发】人工校正切分**） |
| 规则维护成本高 | `PUT /api/rules/{id}` 改规则升版本 + CI 门禁校验（ID 重复/数量<30/类型非法/`advice_ref` 悬空） | 规则需人工编写，扩展靠人 |
| 多格式定位难 | 统一 `full_text` 坐标系，DOCX/PDF/扫描件同构映射，前端只需一种高亮逻辑 | PDF 跨页断句、OCR 阅读顺序错乱时坐标漂移 |
| 长合同性能 | 规则判定耗时实测 1ms（基线 8.4），确定性路径无 LLM 参与 | 大文档全量解析仍受单线程限制 |

---

## 5. 风险共识小结

- 误报靠"视角 + 适用面 + 排除语境 + 共现"四闸门压住，但**规则词表结构性漏判**与**内部 100%≠泛化**是已知残余；
- AI 不出审批结论、只出可溯源意见，是合规底线；
- 所有"系统能否自我纠错/自我校验"类高级能力，当前均未开发，需在路线图中明确。
