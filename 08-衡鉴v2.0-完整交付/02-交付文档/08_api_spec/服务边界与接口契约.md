# 衡鉴 2.0 服务边界与接口契约

> **一句话结论**：衡鉴只提供"合同审查能力"——生成审查意见、只写审批评论区；审批结论、真实 OA、法务裁决等由外部系统负责。本文定义服务边界、33 个接口契约总览、不变量、错误码语义与契约演进策略。

> ⚠️ **与基线核对修正**：基线第七章称「OpenAPI 共 29 个路径」，但源码实际注册 **33 个**（`api/contracts.py` 22 + `api/rules.py` 11）。本文以源码为准列全 33 个，并对偏差留痕。

---

## 1. 服务边界定义

### 1.1 本服务职责（向内）

| 能力域 | 范围 | 实现 |
| --- | --- | --- |
| 文档解析 | docx/pdf/扫描件 → 统一坐标系 | parser_* + coordinator |
| 风险审查 | 确定性规则判定 + LLM 解释增强 | rule_engine + llm |
| 审查意见 | 摘要/结论/画像/报告 | writer + report |
| 任务与状态 | 上传/拉取/流水线/重试/HITL | pipeline + api/contracts |
| 回写 | 只写审批评论区（DRY_RUN + 幂等） | writeback |
| 规则/评测/观测 | 规则编辑、黄金跑分、看板 | rules + eval + audit |

### 1.2 必须由外部系统提供（向外）

| 能力 | 责任方 | 说明 |
| --- | --- | --- |
| 审批结论（通过/拒绝/转交/撤回） | 审批系统/OA | 衡鉴**无任何此类接口**（红线） |
| 真实审批系统对接 | OA/BossPortal | 当前用 `platform_comments` 内置模拟器 |
| 法务人员身份与权限 | 企业 IdP/SSO | 当前 operator 由前端传参（【未开发】鉴权） |
| 多租户与组织隔离 | 外部网关 | 当前单机单租户 |
| 真实盲测泛化评估 | 第三方标注 | 【未开发】，见基线 8.1 |

## 3. 契约不变量（Invariants）

系统必须始终满足，违反即视为缺陷：

1. **坐标不变量**：任何 `findings` 记录必有合法 `char_start/char_end`（`>=0` 且 `end>start`，缺失型规则允许 `-1,-1` 并附文字），且与 `clauses` 同处一个 `full_text` 坐标系。
2. **完成态不变量**：`contracts.status=completed` 时，必有对应 `reviews` 记录（high/medium/low_cnt 与 findings 一致）。
3. **回写成功不变量**：`writebacks.status=success` 必有非空 `platform_comment_id`。
4. **幂等不变量**：相同 `idem_key`（code\|sha256\|rule_version）重复触发回写，返回既有结果并记 `writeback.skip`，不重复写评论。
5. **HITL 门禁不变量**：被 `reject` 后调用 `/writeback` 返回 409（必须先重新审查）。
6. **只写评论不变量**：系统不存在任何修改审批结论（通过/拒绝/转交/撤回）的接口。
7. **响应约定不变量**：成功直接返回业务对象，无 `{code,data,msg}` 包装；失败返回 `{"detail":"可读中文原因"}`，状态码∈{400,404,409,413,500}；响应头带 `X-Process-Time-Ms` 与 `X-HengJian-Version`。
8. **SSE 格式不变量**：`data: {"seq","contract_id","stage","message","progress","level","ts","extra"}`。

## 4. 错误码语义表

| 状态码 | 触发场景（源码核对） | 示例 |
| --- | --- | --- |
| 400 | 缺文件名；不支持的文件类型；规则更新无字段；不支持的审核动作；`edit` 无 edits；`reject` 非 completed | "不支持的文件类型：.xls" |
| 404 | 合同不存在；风险项不存在；示范条款不存在；缺少文档记录 | "合同不存在：99" |
| 409 | 未 completed 不可回写；被 reject 不可回写；`approve/edit/reject` 非 completed；无可驳回结果 | "审查结果已被驳回，请重新发起审查" |
| 413 | 上传文件超过 `HJ_MAX_UPLOAD_MB`（默认 30MB） | "文件超过 30MB 上限" |
| 500 | 文档重渲染失败；PDF 生成失败；评测执行异常 | "PDF 生成失败：..." |

> 设计原则：业务可预期错误用 4xx（客户端/状态问题），系统意外用 5xx；所有 `detail` 为中文可读原因，便于前端 `toast` 直显。

## 5. 契约演进策略

### 5.1 版本化
- 当前为 v2.0.0（`config.PROJECT_VERSION`），响应头 `X-HengJian-Version` 标识。
- 规则版本独立演进（`rule_version`，每次 `PUT /rules/{id}` 升级），并写入 `findings.rule_version`/`reviews.rule_version`/`eval_runs.rule_version`，保证命中可追溯当时规则。

### 5.2 向后兼容
- 新增字段默认追加，**不删不改既有字段名/类型**（避免前端断裂）。
- 列表类接口保持 `items`/`total` 结构；详情保持对象直接返回。

### 5.3 废弃流程
1. 在本文档与基线标记 **【已废弃】** 并注明替代接口与废弃日期；
2. 保留至少 1 个发布周期后仍返回（可加 `deprecated:true` 提示）；
3. 前端迁移完成后，后端移除路由并同步更新冒烟脚本（`tools/smoke_api.py` 57~64 项断言）。

### 5.4 未实现能力标注
- 任何描述但代码未提供的接口/字段，统一标 **【未开发】**（如真实 OA 对接、鉴权、盲测集、审计归档）。
- 禁止伪造功能或数据；`/eval/score` 在未跑过时返回 `has_result:false` 而非编造数字。
