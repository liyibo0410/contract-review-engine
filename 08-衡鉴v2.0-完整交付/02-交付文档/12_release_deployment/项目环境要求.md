# 衡鉴 · 项目环境要求

> **一句话结论**：只需要一台装了 **Python 3.11+** 的机器就能完整运行 ——
> 不需要 MySQL、不需要 Redis、不需要消息队列、不需要 Node.js；
> 唯一的"重"依赖是可选安装的 OCR 引擎（纯 pip 包，无系统级依赖）。

---

## 一、硬件要求

| 项 | 最低 | 推荐 | 说明 |
| --- | --- | --- | --- |
| CPU | 双核 2.0 GHz | 四核 2.5 GHz+ | 解析与规则判定都是 CPU 密集但量很小 |
| 内存 | 2 GB | 4 GB+ | 装 OCR 后 onnxruntime 常驻约 300 MB |
| 磁盘 | 2 GB 可用 | 10 GB+ | 代码 + 依赖约 500 MB（含 OCR onnx 模型）；每份报告约 60 KB |
| 显示 | 无要求（服务端） | 1280×800+ | 前端工作台为双栏布局，低于 1180px 会退化为单栏 |
| 网络 | **可完全离线** | 需互联网 | 仅"大模型语义增强"与此可选；离线时自动降级为模板生成器 |

**磁盘占用明细**（实测）：

| 项 | 大小 |
| --- | --- |
| Python 依赖（不含 OCR） | ≈ 90 MB |
| OCR 引擎（rapidocr-onnxruntime + onnxruntime + opencv） | ≈ 310 MB |
| 样例合同 13 份 | ≈ 1 MB |
| Docker 镜像（多阶段构建后） | ≈ 1.1 GB |

## 二、软件要求

### 2.1 必需

| 项 | 版本 | 校验命令 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 · Linux（glibc ≥ 2.28）· macOS 12+ | —— |
| Python | **≥ 3.11**（实测 3.13.14） | `python --version` |
| 包管理器 | uv 0.5+（也可用 pip） | `uv --version` |

### 2.2 可选

| 项 | 用途 | 不装的后果 |
| --- | --- | --- |
| `rapidocr-onnxruntime` | 扫描件 OCR | 扫描件任务进入 `blocked`（`OCR_ENGINE_UNAVAILABLE`），其他格式不受影响 |
| 大模型 API Key（任意 OpenAI 兼容） | 成因解释、建议润色、跨条款矛盾检测 | 语义层降级为确定性模板生成器，**结论与建议不变** |
| Docker 20.10+ / Docker Compose v2 | 容器化部署 | 只能用本机直接运行方式 |
| Git | 版本管理 | 无法使用 CI 与变更追溯 |
| 浏览器 Chrome / Edge 90+ | 前端控制台 | 需支持 SSE 与 CSS Grid |

### 2.3 明确不需要（重要）

| 项 | 为什么不需要 |
| --- | --- |
| MySQL / PostgreSQL | 用 SQLite（标准库 `sqlite3`，WAL 模式） |
| Redis / RabbitMQ / Kafka | 进度事件走进程内 EventBus + SSE，单机无跨进程需求 |
| Node.js / npm / webpack | 前端零构建：原生 HTML/CSS/JS，无 CDN 外链 |
| LibreOffice / wkhtmltopdf | 报告 PDF 由 PyMuPDF 内置中文字体直出 |
| systemd 以外的进程管理器 | 用 `start.bat` / Docker / systemd 均可 |

## 三、Python 依赖清单

来自 `pyproject.toml`：

| 包 | 用途 | 是否必需 |
| --- | --- | --- |
| `fastapi` | Web 框架 + OpenAPI 契约 | ✅ |
| `uvicorn[standard]` | ASGI 服务器 | ✅ |
| `python-multipart` | multipart 文件上传解析 | ✅ |
| `PyYAML` | 规则库与示范条款库加载 | ✅ |
| `python-docx` | DOCX 段落树解析 | ✅ |
| `PyMuPDF` | PDF 解析 + 报告 PDF 生成 | ✅ |
| `pillow` | 图片读取（OCR 前置）与样例扫描件生成 | ✅ |
| `rapidocr-onnxruntime` | 扫描件 OCR | 可选（验收项涉及扫描件，建议装） |
| `pytest` | 单元测试 | 开发必需 |
| `httpx` | 接口冒烟（ASGI 直连） | 开发必需 |

**依赖设计取舍**：LLM 调用使用**标准库 `urllib`** 而非 `openai` SDK ——
少一个依赖就少一个演示现场出问题的理由，且 OpenAI 兼容协议本身足够简单。

## 四、安装步骤

### 4.1 标准安装（uv）

```bash
cd hengjian
uv venv --python 3.11 .venv
uv pip install --python .venv/Scripts/python.exe -e .
uv pip install --python .venv/Scripts/python.exe rapidocr-onnxruntime   # 可选
cd backend && ../.venv/Scripts/python.exe tools/gen_samples.py
```

### 4.2 网络受限环境

若直连 PyPI 超时或报 TLS 错误，改用国内镜像：

```bash
uv pip install --python .venv/Scripts/python.exe \
  --index-url https://mirrors.aliyun.com/pypi/simple/ -e .
```

若 `uv venv` 卡在下载解释器（需要访问 GitHub），
改为**显式指定本机已有解释器**：

```bash
uv venv --python "C:\Users\<用户名>\.workbuddy\binaries\python\versions\3.13.12\python.exe" .venv
```

### 4.3 纯 pip 兜底

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install fastapi "uvicorn[standard]" python-multipart \
  PyYAML python-docx PyMuPDF pillow
```

### 4.4 装完自检

```bash
.venv/Scripts/python.exe -c "import fastapi, uvicorn, yaml, docx, fitz, PIL; print('core OK')"
.venv/Scripts/python.exe -c "import rapidocr_onnxruntime; print('ocr OK')"   # 可选
cd backend && ../.venv/Scripts/python.exe -m pytest -q          # 期望 39 passed
```

## 五、端口与网络要求

| 端口 | 用途 | 是否需对外 |
| --- | --- | --- |
| 8130 | 应用（API + 静态前端） | 内网访问即可；对外需经网关 + SSO |
| 8080 | 可选 Nginx 反代 | 视部署方案 |
| 出网 443 | 大模型 API（可选） | 仅启用 LLM 时 |

**防火墙/代理注意事项**：若运行环境设置了 `HTTP_PROXY` / `HTTPS_PROXY`，
LLM 调用代码已显式绕过系统代理（`urllib.request.ProxyHandler({})`）直连，
避免"本机代理把请求拦成 502"这类难以定位的问题。

## 七、初始化与重置

| 目的 | 操作 |
| --- | --- |
| 首次初始化 | 启动服务即自动建表（`db.init_db()`），无需手工建库 |
| 重新生成样例合同 | `cd backend && python tools/gen_samples.py`（会覆盖样例外加更新黄金标注） |
| 清空全部业务数据 | 删除 `backend/data/hengjian.db`（含 `-wal` / `-shm`）后重启 |
| 重置演示数据 | `python demo.py --fresh` |
| 恢复规则库 | `git checkout -- app/rules/`（**先确认没有需要保留的本地改动**） |

## 八、环境相关的已知坑（实测记录）

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| `uv venv` 报 `Request failed after 3 retries` | 需从 GitHub 下载 python-build-standalone | 用 `--python <本机解释器路径>` 指定已有解释器 |
| `uv pip install` 报 `tls handshake eof` | 直连 PyPI 被网络策略拦截 | 加 `--index-url https://mirrors.aliyun.com/pypi/simple/` |
| `pytest` 输出中文乱码 | 控制台代码页与 UTF-8 冲突 | 设 `PYTHONIOENCODING=utf-8`；重定向用 `\| Out-File -Encoding utf8` |
| 脚本输出的日志文件读出来是乱码 | PowerShell `>` 默认写 UTF-16 | 改用 `\| Out-File -Encoding utf8` |
| 从脚本启动的服务很快退出 | 受限环境回收子进程 | 长期运行请用 systemd / Docker，不要前台脚本拉起 |
| 测试写进了真实数据库 | `app.config` 在 import 时就读了 `HJ_DB` | 环境变量必须在 `conftest.py` 中、任何 `app.*` 导入之前设置 |
