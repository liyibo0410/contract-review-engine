# 衡鉴 · 演示脚本

> **一句话结论**：3 分钟演示，覆盖「拉取 → 解析 → 定位 → 修改 → 回写 → 异常 → 评测」七幕，
> 全程可重复运行；每一幕都给出**操作动作 + 预期结果 + 一句台词**，另有备用台词应对提问。

| 项 | 值 |
| --- | --- |
| 总时长 | **3 分钟**（紧凑版）/ 6 分钟（含讲解版） |
| 主用例 | `01_软件采购合同_埋雷版.docx`（6 条高风险） |
| 异常用例 | `13_软件采购合同_加密件.pdf`（阻塞与重试） |
| 演示前置 | `start.bat` 已启动，浏览器已打开大盘 |

## 一、演示前检查（2 分钟，务必做）

| # | 检查项 | 命令 / 动作 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 服务已启动 | 打开 `http://127.0.0.1:8130/` | 大盘正常渲染，顶栏指示灯亮 |
| 2 | 数据干净 | `python demo.py --fresh` | 清空历史任务后重新生成演示数据 |
| 3 | 规则库完整 | 顶栏显示"规则 32 条 / v1.0.0" | 数量与版本正确 |
| 4 | OCR 就绪 | 顶栏「OCR 就绪」为绿灯 | 若为红灯，扫描件演示跳过 |
| 5 | 语义层状态 | 顶栏「语义层」在线或"降级模板" | **两者都正常**，降级不影响演示 |
| 6 | 评测已跑过一次 | 打开评测页 | 指标卡有数字（不是"尚未执行过评测"） |
| 7 | 报告目录可写 | `backend/data/reports/` 存在 | 导出时不会报错 |
| 8 | 浏览器窗口大小 | 宽度 ≥ 1200px | 工作台双栏布局不塌成单栏 |

**彩排建议**：完整跑 2 遍，第 2 遍掐表。若想更保险，把 `HJ_WRITEBACK_DRY_RUN=1` 放进 `.env`，
则回写永远停在预览态，绝不会污染审批评论区。

## 二、七幕演示

### 第 1 幕 · 开场（15 秒）

| 项 | 内容 |
| --- | --- |
| **动作** | 打开大盘首页，鼠标从左到右划过统计卡与任务列表 |
| **预期** | 四张统计卡有数字；列表按"高风险优先"排序 |
| **台词** | "这是衡鉴，一套企业合同智能审查系统。左边是我的待审任务，**风险高的自动排在最上面**。" |
| **要点** | 不要急着讲技术。先让评委看到"这是一个真实在跑的系统"，而不是 PPT |

### 第 2 幕 · 拉取与解析（25 秒）

| 项 | 内容 |
| --- | --- |
| **动作** | ①点「从审批系统拉取待办任务」②指向右侧「实时流水线」时间轴 |
| **预期** | 列表出现 3 条任务；状态从"待处理"依次变"解析中 → 审查中 → 审查完成"；时间轴逐条点亮并显示耗时；进度条走满 |
| **台词** | "任务是从审批系统拉过来的。系统自动完成解析和审查 —— 这份 4 页的合同，解析加规则判定不到 1 秒。" |
| **要点** | 时间轴上的每条消息都是**真实事件**（走 SSE 推送），不是动画 |

### 第 3 幕 · 定位（40 秒）★ 核心

| 项 | 内容 |
| --- | --- |
| **动作** | ①点开埋雷版合同进工作台 ②点右侧「知识产权归属相对方」高风险卡 ③再在左侧划选"到货即付全款"那句 |
| **预期** | ②左侧**平滑滚动到第 2 页并高亮脉冲**，该段出现蓝色高亮底；③弹出「片段研判」窗口，显示该片段涉及的 2 条风险 |
| **台词** | "多数同类方案只会给你一段结论文字。我们做的是**证据链** —— 点风险，跳到原文那一句；反过来，在原文里划一句话，也能查出它涉及哪几条风险。**双向的。**" |
| **要点** | 这是全场最重要的一幕，**放慢速度**。可以补一句："字符级定位，不是段落级。" |

### 第 4 幕 · 修改建议（30 秒）

| 项 | 内容 |
| --- | --- |
| **动作** | ①展开某条风险的「成因 / 依据 / 示范条款」②点「采纳建议」，把推荐条款里的"30%"改成"20%"后确认 |
| **预期** | 折叠区显示三段：成因、法律依据（法条名）、推荐修改条款；采纳后卡片出现"已采纳"标记；界面提示已生成修改前后对照 |
| **台词** | "每条风险配一段可直接落地的替代条款，来源是我们的标准条款库，不是让模型自由发挥 —— 因为**这句话是要写进合同、要承担法律后果的**。法务可以改完再采纳。" |
| **要点** | 顺手演示键盘流：按 `j` 切下一条风险，说明"给每天看几十份合同的人准备的" |

### 第 5 幕 · 回写（25 秒）

| 项 | 内容 |
| --- | --- |
| **动作** | ①切到「结论与回写」②点「预览意见（DRY_RUN）」③关掉弹窗，点「写回审批意见」④**再点一次** |
| **预期** | ②弹窗显示将写入的 Markdown 正文；③提示"已写回审批系统评论区"，评论区出现意见；④提示"已回写成功，本次跳过" |
| **台词** | "回写前一定先给你看一遍要写什么。写回之后 —— 注意，**我再点一次**：系统说已跳过。因为幂等。同一份文件、同一版规则，无论触发多少次，评论区只会有一条意见。" |
| **要点** | 第 ④ 步是加分项，能体现工程素养。补一句："系统只写评论，**不存在通过/拒绝的接口** —— 审批结论永远是人做的。" |

### 第 6 幕 · 异常处理（20 秒）

| 项 | 内容 |
| --- | --- |
| **动作** | ①回到大盘，上传 `13_软件采购合同_加密件.pdf` ②等它变"解析受阻" ③点「重新解析 / 重试」 |
| **预期** | ②状态变红"解析受阻"，原因明确写"文档已加密，无法解析正文，请上传去除密码的版本或提供打开密码"；③重试后仍受阻（文件没换）且不产生脏数据 |
| **台词** | "演示系统最容易在这里出事 —— 出个错就卡住了。我们的做法是把失败**分类**：加密、扫描件模糊、引擎缺失，是三种完全不同的问题，处理方式也完全不同。所以重试是有意义的，不是碰运气。" |
| **要点** | 强调"重试仍失败**是预期行为**"，不是缺陷。若被问"为什么重试没用"，答："因为文件没换，重试本来就不该成功。" |

### 第 7 幕 · 收尾（25 秒）

| 项 | 内容 |
| --- | --- |
| **动作** | ①打开评测页 ②指向指标卡 ③回到工作台，点「导出报告」→「下载 PDF」 |
| **预期** | ①六张指标卡：高风险召回 100%、误报 0、准确率 100%、解析成功率 100% 等；②浏览器下载一份中文 PDF |
| **台词** | "最后说一组数字：13 份黄金样例，**高风险召回率 100%，误报 0**。但我要补一句诚实的：这套样例是我们自己标注的，所以它是**回归基线**，用来防止改规则时改坏别的地方 —— **不等于**我们见过所有合同。我们已经把第三方盲测列进了路线图。" |
| **要点** | 主动说局限，比被问到再解释更可信 |

## 三、完整台词稿（连贯版，约 3 分钟）

> "这是衡鉴，一套企业合同智能审查系统。左边是我的待审任务，风险高的自动排最上面。
>
> 任务从审批系统拉过来，系统自动完成解析和审查 —— 这份四页的合同，解析加规则判定不到一秒。
>
> 现在点开它。多数同类方案只会给你一段结论文字；我们做的是**证据链**：
> 点右侧这条'知识产权归属相对方'，左侧直接跳到第 2 页并高亮那一句。
> 反过来，我在原文里划一段话 —— 看到没，它告诉我这段涉及哪两条风险。**双向定位，字符级。**
>
> 每条风险都配了一段可直接落地的替代条款，来源是标准条款库而不是模型自由发挥，
> 因为这句话是要写进合同、要担法律后果的。法务可以改完再采纳。
>
> 复核完点写回。回写前一定先给你看要写什么 —— 写回之后，**我再点一次**：
> 系统说已跳过。同一份文件、同一版规则，无论点几次，评论区只会有一条。
> 而且请注意，系统**只有写评论的能力**，不存在通过或拒绝的接口 —— 审批结论永远是人做的。
>
> 最后看异常。上传一份加密合同 —— 它变成'解析受阻'，并明确告诉我原因。
> 演示系统最容易在这里卡住；我们把失败分了类：加密、扫描件模糊、引擎缺失，
> 是三种不同的问题，处理方式完全不同，所以重试是有意义的。
>
> 一组数字收尾：13 份黄金样例，高风险召回率 100%，误报 0。
> 但我要诚实补一句：这套样例是我们自己标注的，所以它是**回归基线**，
> 用来防止改规则时改坏别的地方 —— 不等于我们见过所有合同。第三方盲测已经在路线图里了。"

## 四、预设问答（被问到时的应答）

| 提问 | 应答要点 |
| --- | --- |
| "结论是大模型给的吗？" | **不是。** 判定由 32 条 YAML 规则完成，可复现、可审计；大模型只解释成因、润色建议、查条款矛盾，且 Prompt 里明确禁止新增/修改风险项，输出要过结构校验 |
| "如果大模型挂了怎么办？" | 超时 8 秒或返回非法即降级为确定性模板生成器，摘要、建议、结论一样不少。现在演示这台机器就没配 Key |
| "100% 召回率是真的吗？" | 真的，但它衡量的是"在我们自己标注的样例集上没有漏报和误报"，是**回归基线**。泛化能力需要第三方盲测，已列路线图 |
| "为什么不用大模型直接判？" | 法务场景要求结论可解释、可复核、可追溯、可审计。模型自由判断四条里至少违反三条 |
| "扫描件识别不准怎么办？" | 低置信度时不硬着头皮出结果，而是进入阻塞态并给出可读原因，让用户换清晰件 —— 错报比不报更危险 |
| "和别的方案差在哪？" | ①字符级双向定位的证据链；②规则主判定 + 视角解析（采购/销售同一句话结论相反）；③可降级；④幂等回写与状态机 |
| "能接真实审批系统吗？" | 能。回写适配器位置已预留（替换一个函数），幂等与状态机逻辑完全复用。当前是内置模拟器，如实说明【未开发】 |
| "为什么数据量这么小也能叫系统？" | 单部门日常审查量（每天几份到几十份）单机足够；扩容路径已写明（EventBus 换 Redis/MQ） |
| "有没有做权限？" | **【未开发】**，这是明确的短板，列在路线图 M1，也是上线前必须补的项 |
| "总共写了多少代码？" | git 追踪 58 个文件：后端 30 个 Python、前端 10 个静态文件、配置与文档若干；39 项单测 + 64 项接口冒烟全通过 |

## 五、应急方案

| 状况 | 处理 |
| --- | --- |
| 服务起不来 | 改用**离线兜底**：`python demo.py --fresh` 走命令行演示，输出每一步的真实结果（含命中明细与坐标） |
| 浏览器崩溃 | 备份浏览器（Edge ↔ Chrome 各开一个窗口） |
| 网络断了 | 全链路本地运行，**不影响**；语义层本来就是模板降级状态 |
| 大模型超时 | 本来就降级，无需处理；可顺带解释降级机制 |
| OCR 引擎报错 | 跳过第 6 幕的扫描件部分，只演示加密件阻塞 |
| 回复太慢 | 演示前把浏览器缓存预热一遍（大盘 + 工作台 + 评测页各开一次） |
| 时间不够 | **保留第 3 幕（定位）与第 5 幕（回写幂等）**，这两幕信息量最高；其余可口头带过 |

## 六、不可省略的三句话

无论时间多紧，这三句一定要说到：

1. **"系统只写意见，不改审批结论。"** —— 这是边界，也是可信的基础。
2. **"每条结论都能点到原文那一句。"** —— 这是技术壁垒，也是法务敢用的前提。
3. **"100% 召回是内部回归基线，不是泛化能力。"** —— 主动说局限，比被追问后解释更有说服力。
