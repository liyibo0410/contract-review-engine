七层技术架构（运行时视角）

层构成职责
① 接入层本地上传 / 审批待办拉取接收合同与任务来源
② 编排层pipeline.py状态机 · 幂等 · 阻塞重试 · SSE 事件总线
③ 解析层parser_docx / pdf / ocr + coordinator三格式 → 统一坐标系（段落树 + 页码 + 字符区间）
④ 审查层rule_engine（32 条）→ llm（可降级）规则下判定，模型做表达
⑤ 回写层writer / writeback / report意见组装 · DRY_RUN · 幂等回写 · 报告导出
⑥ 数据层SQLite(WAL) 10 张表任务 / 条款 / 命中 / 意见 / 回写 / 审计 / 评测 / HITL
⑦ 观测层audit_logs / eval_runs / health留痕 · 跑分 · 健康检查

工程红线（不可突破）

  • 只写意见，不改结论 —— 系统不存在通过 / 拒绝 / 转交 / 撤回接口。
  • 规则主判定，模型只增强 —— 风险等级只能由规则引擎产出；LLM 输出必须过结构校验。
  • 坐标唯一真理 —— 任何风险必须可溯源到 clauses 表的字符区间。
  • 幂等三键 —— 合同编号 + 附件 SHA256 + 规则版本号；回写前强制 DRY_RUN。
  • 审计留痕 —— 每个链路步骤必须写 audit_logs。
  • 演示零事故 —— 外部依赖（LLM / OCR / 网络）全部有降级路径。

数字的诚实口径

  • 高风险召回 100%（11/11）、误报 0 —— 实测，可复现。
  • 但这套黄金标注与规则库同源编写，因此它是 内部回归基线， 用于防止"改一条规则、伤三处条款"，不等于面对全新合同的泛化能力。
  • 泛化能力需第三方独立标注的盲测集，已列入路线图 M2。
